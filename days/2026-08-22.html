モデル前の FilesetResolver 初期化時間を測るストップウォッチ

A stopwatch for FilesetResolver initialization before model loading

Google AI Edge の MediaPipe Tasks Vision JavaScript API、FilesetResolver class、公式 MediaPipe Tasks Web demo repository、LiteRT.js guide を参考に、モデルを読む前の WASM fileset 初期化を実測する自作サンプルを追加しました。`@mediapipe/tasks-vision` の ESM import、`FilesetResolver.isSimdSupported()`、`FilesetResolver.forVisionTasks()`、WASM path 切り替え、初回インタラクション予算、warm run 履歴をブラウザ上で可視化します。

今日の重要トピック

  1. MediaPipe Tasks Vision の多くの Web 実装は、具体的な detector / segmenter / landmarker を作る前に `FilesetResolver.forVisionTasks()` で WASM fileset を解決する。

    Many MediaPipe Tasks Vision Web implementations resolve a WASM fileset through `FilesetResolver.forVisionTasks()` before creating a concrete detector, segmenter, or landmarker.

  2. `FilesetResolver.isSimdSupported()` は SIMD 経路の可否を事前に見られるため、同じタスクでも初期化・推論予算の読み方を変える材料になる。

    `FilesetResolver.isSimdSupported()` exposes whether the SIMD path is available, which changes how initialization and inference budgets should be read.

  3. 公式 mediapipe-samples-web は Face / Hand / Pose / Object / Segmenter などの実タスクを横断しているが、今日のカードは外部デモ一覧ではなく初期化計測の自作 UI に限定した。

    The official mediapipe-samples-web project spans real Face, Hand, Pose, Object, and Segmenter tasks, but today's card centers on an original initialization measurement UI rather than an external demo list.

  4. LiteRT.js は custom `.tflite` と WebGPU / WebNN の別ルートであり、MediaPipe Tasks の fileset 初期化コストと並べると、ready-made Task と custom runtime の設計境界が見えやすい。

    LiteRT.js is the separate route for custom `.tflite` models plus WebGPU / WebNN, so comparing it conceptually with MediaPipe Tasks fileset initialization clarifies the ready-made Task versus custom runtime boundary.

  5. WASM path を CDN と自前ホストで比較できる小さな計測器は、GitHub Pages や静的ホスティングで MediaPipe Tasks を公開する前の確認に使える。

    A small tool that compares CDN and self-hosted WASM paths is useful before publishing MediaPipe Tasks on GitHub Pages or other static hosts.

注目事例と何が面白いか

Notable example and why it matters

今日の注目は、推論結果ではなく推論が始まる前の初期化レイヤーです。公式 README の各 Vision Task 例では、Face Detector、Image Segmenter、Interactive Segmenter などを作る前に `FilesetResolver.forVisionTasks()` を呼んでいます。自作サンプルではこの共通入口だけを取り出し、ESM import、SIMD probe、fileset resolver の時間を分けて計測することで、モデル選択より前に見落としがちな待ち時間を UI にしました。

Today's notable angle is the initialization layer before inference output exists. The official README examples call `FilesetResolver.forVisionTasks()` before creating tasks such as Face Detector, Image Segmenter, and Interactive Segmenter. The original sample isolates that shared entry point and measures ESM import, SIMD probing, and fileset resolver timing separately, turning an often-hidden pre-model delay into a visible UI.

表現・インタラクションのアイデア

Expression and interaction idea

Run Timing を押すと `@mediapipe/tasks-vision` を import し、SIMD 判定、`forVisionTasks()` 初期化を順に走らせます。Run 3x では同じブラウザ上の warm run 履歴を棒グラフ化します。ユーザーは WASM fileset path を CDN / 旧バージョン / custom URL で切り替え、初回インタラクション予算、モデル読み込み placeholder、目標 FPS を動かして、prewarm すべきか lazy load でよいかを確認できます。

Pressing Run Timing imports `@mediapipe/tasks-vision`, checks SIMD, and runs `forVisionTasks()` in sequence. Run 3x charts warm-run history in the same browser. The user can switch the WASM fileset path between CDN, an older version, or a custom URL, then adjust first-interaction budget, model-load placeholder, and target FPS to decide whether prewarming or lazy loading is acceptable.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

蓄積できるデータは ESM import 時間、SIMD 判定時間、SIMD 可否、`forVisionTasks()` 時間、WASM path、失敗メッセージ、warm run の総時間、初回インタラクション予算、想定モデル読み込み時間、目標 FPS です。IndexedDB に保存すれば、Face / Hand / Pose / Object / Segmenter などの Task 別に、モデル前の共通初期化コストと実推論コストを分離して比較できます。Worker 化や OffscreenCanvas 化の前提ログとしても使えます。

The sample can accumulate ESM import time, SIMD probe time, SIMD availability, `forVisionTasks()` time, WASM path, failure messages, warm-run total time, first-interaction budget, assumed model-load time, and target FPS. Saved to IndexedDB, this can separate common pre-model initialization cost from real inference cost for Face, Hand, Pose, Object, and Segmenter tasks. It also becomes a prerequisite log before Worker or OffscreenCanvas work.

制作に使えそうな技術メモ

Production note

静的サイトで MediaPipe Tasks を配る場合、Task API の実装より先に WASM path、CORS、バージョン固定、SIMD availability、初回クリック後の待ち時間を確認する必要があります。CDN の `@latest` は検証には便利ですが、公開サンプルでは version pinning した方が再現性があります。今日の HTML は `@mediapipe/tasks-vision@0.10.22/+esm` を固定し、fileset path も UI で見えるようにしました。

When shipping MediaPipe Tasks on a static site, WASM path, CORS, version pinning, SIMD availability, and post-click wait time should be checked before the task implementation itself. CDN `@latest` is convenient for exploration, but pinned versions make public samples more reproducible. Today's HTML pins `@mediapipe/tasks-vision@0.10.22/+esm` and exposes the fileset path in the UI.
