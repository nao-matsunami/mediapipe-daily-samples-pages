今日の重要トピック

  1. MediaPipe Solutions は Google AI Edge の一部として整理され、Web では `@mediapipe/tasks-vision` 経由で Hand / Pose / Face / Gesture などの Vision Tasks を利用できる。

    MediaPipe Solutions are organized under Google AI Edge, and web apps can use Vision Tasks such as Hand, Pose, Face, and Gesture through `@mediapipe/tasks-vision`.

  2. Hand Landmarker は静止画像、動画フレーム、ライブ映像を入力にでき、image coordinates の landmarks、world coordinates の landmarks、handedness を出力する。

    Hand Landmarker accepts still images, video frames, and live video, and outputs image-coordinate landmarks, world-coordinate landmarks, and handedness.

  3. Web 実装では `FilesetResolver.forVisionTasks()` で Wasm fileset を解決し、`HandLandmarker.createFromOptions()` で model asset、running mode、confidence threshold を設定する。

    On the web, `FilesetResolver.forVisionTasks()` resolves the Wasm fileset, while `HandLandmarker.createFromOptions()` configures the model asset, running mode, and confidence thresholds.

  4. Video / live stream では `detectForVideo()` と timestamp を使い、tracking confidence が低い時は再検出に戻るため、latency と安定性の UI 表示が重要になる。

    For video and live streams, `detectForVideo()` uses timestamps, and low tracking confidence can cause the task to fall back to detection, making latency and stability UI important.

  5. Legacy Hands は 2023-03-01 以降、新しい MediaPipe Solutions に移行済みだが、palm detector と hand landmark model の 2 段 pipeline 理解にはまだ参考になる。

    Legacy Hands moved to the newer MediaPipe Solutions after 2023-03-01, but its two-stage palm detector plus hand landmark model overview remains useful for understanding the pipeline.

注目事例と何が面白いか

Notable example and why it matters

今日の注目は Hand Landmarker for Web の導入フローです。`@mediapipe/tasks-vision`、Wasm fileset、`.task` model asset、`VIDEO` running mode、`detectForVideo()` という最小構成で、ブラウザー内のライブ映像に手の 21 点ランドマークを重ねられます。面白いのは、モデル自体よりも「モデルロード」「カメラ権限」「tracking が効いている時の軽いフレーム」「再検出に戻る重いフレーム」を UI 側で見せる必要がある点です。

Today's notable reference is the Hand Landmarker for Web setup flow. With `@mediapipe/tasks-vision`, a Wasm fileset, a `.task` model asset, `VIDEO` running mode, and `detectForVideo()`, a browser can overlay 21 hand landmarks on live video. The interesting part is not only the model itself, but the UI need to expose model loading, camera permission, lighter tracking frames, and heavier re-detection frames.

表現・インタラクションのアイデア

Expression and interaction idea

初回サンプルは、MediaPipe の実行有無をアプリの中心にせず、常に 21 点の手が見える latency probe にしました。`Try Camera` は CDN から Tasks Vision と hand landmarker model を読み込み、許可されれば実 `detectForVideo()` を使います。失敗時は deterministic な合成手に戻り、Open / Pinch / Fist / Point、detection confidence、tracking confidence、smoothing、frame budget を触って pipeline 判定と jitter を観察できます。

The first sample is a latency probe that always shows a 21-point hand instead of making real MediaPipe availability the entire experience. `Try Camera` loads Tasks Vision and the hand landmarker model from the CDN and uses real `detectForVideo()` when permitted. On failure it falls back to a deterministic synthetic hand, where Open / Pinch / Fist / Point, detection confidence, tracking confidence, smoothing, and frame budget can be adjusted to observe pipeline state and jitter.

制作に使えそうな技術メモ

Production note

Web の Hand Landmarker は `runningMode: "VIDEO"` の時に `detectForVideo(video, timestamp)` を使います。実運用では `video.currentTime` が前回と同じなら推論を飛ばす、モデルロードは user gesture の後に開始する、`minHandDetectionConfidence` と `minTrackingConfidence` を UI の品質表示に接続する、`worldLandmarks` がある時だけ 3D 表現へ昇格する、という分岐が扱いやすいです。カメラが無い環境でも UI を確認できるよう、合成ランドマーク fallback を持つと開発速度が上がります。

With `runningMode: "VIDEO"`, the web Hand Landmarker uses `detectForVideo(video, timestamp)`. In production, skip inference when `video.currentTime` has not changed, start model loading after a user gesture, connect `minHandDetectionConfidence` and `minTrackingConfidence` to visible quality states, and only promote to 3D rendering when `worldLandmarks` are available. A synthetic landmark fallback keeps UI development moving even without camera access.

Then lower Tracking confidence to increase jitter and reduce quality, and raise Smoothing to stabilize points while making response feel slower. In a camera-capable environment, press `Try Camera` and check whether the real model loads, or inspect the fallback log if it fails.
