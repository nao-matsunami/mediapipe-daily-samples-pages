今日の重要トピック

  1. Hand Landmarker の Web guide は `detect()` / `detectForVideo()` が同期実行で UI thread を塞ぎ得るため、camera/video frames では web workers を使う設計を推奨している。

    The Hand Landmarker Web guide states that `detect()` / `detectForVideo()` run synchronously and may block the UI thread, so workers are recommended for camera/video frames.

  2. Hand Landmarker の Web 設定は `runningMode`、`numHands`、`minHandDetectionConfidence`、`minHandPresenceConfidence`、`minTrackingConfidence` が中心で、Video mode では presence/tracking confidence が detector 再実行の判断に関わる。

    The core Hand Landmarker Web options are `runningMode`, `numHands`, `minHandDetectionConfidence`, `minHandPresenceConfidence`, and `minTrackingConfidence`; in Video mode, presence and tracking confidence affect whether the detector is triggered again.

  3. Gesture Recognizer も Web で `runningMode` と hand confidence 系の設定を持ち、canned gestures の score threshold / allowlist / denylist を使って UI イベントの誤発火を抑えられる。

    Gesture Recognizer has similar Web running-mode and hand-confidence settings, and canned gesture score threshold / allowlist / denylist options can reduce accidental UI triggers.

  4. 公式 mediapipe-samples-web の Hand Landmarker worker は `ImageBitmap` と timestamp を受け、必要に応じて IMAGE / VIDEO mode を切り替え、処理後に bitmap を close する構成だった。

    The official mediapipe-samples-web Hand Landmarker worker receives an `ImageBitmap` and timestamp, switches IMAGE / VIDEO mode when needed, and closes the bitmap after processing.

  5. npm 確認では 2026-09-04 JST 時点で `@mediapipe/tasks-vision` は 1.0.1、`@mediapipe/tasks-genai` は 0.10.29 だった。

    An npm check on 2026-09-04 JST showed `@mediapipe/tasks-vision` at 1.0.1 and `@mediapipe/tasks-genai` at 0.10.29.

注目事例と何が面白いか

Notable example and why it matters

今日の注目は Hand Landmarker を video/camera frames で使う時の worker 境界です。公式 guide は `detectForVideo()` の同期実行が UI thread を塞ぎ得ることを明記しており、公式サンプル側も worker に `ImageBitmap` と timestamp を渡す構成になっています。推論の前に「どのフレームを送るか」「busy 中に捨てるか」「結果遅延をどう見せるか」を UI として触れるようにするのが面白い点です。

Today's notable example is the worker boundary for using Hand Landmarker on video or camera frames. The official guide says `detectForVideo()` can block the UI thread, and the official sample sends `ImageBitmap` plus timestamps into a worker. The useful part is making frame submission, busy skipping, and result latency visible before wiring real inference.

表現・インタラクションのアイデア

Expression and interaction idea

本命サンプル `Hand Worker Frame Gate` は、疑似手フレームを描きながら、motion delta が低いフレームは捨て、worker busy 中は skip し、返ってきた result をタイムラインで青く表示します。派生の `Gesture Event Debounce Lab` は、その結果をさらに gesture category のスコア列とみなし、score threshold、連続一致数、cooldown から UI コマンドを発火します。外部デモの一覧ではなく、実装前に調整すべき状態遷移だけを自作の操作面にしました。

The main sample, `Hand Worker Frame Gate`, draws synthetic hand frames, drops low-motion frames, skips while a worker is busy, and marks returned results in blue on a timeline. The derivative `Gesture Event Debounce Lab` treats that stream as gesture-category scores and fires UI commands from a score threshold, consecutive confirmations, and cooldown. Instead of listing external demos, both samples expose the state transitions that need tuning before production inference.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

蓄積できるデータは、フレーム番号、motion delta、send/skip/result イベント、疑似 inference latency、threshold、worker busy 率、gesture top score、streak、cooldown、発火した command です。これを実 Hand Landmarker の 21 点 landmarks、world landmarks、handedness、Gesture Recognizer の canned gesture、Object Detector の bbox、Image Segmenter の mask、Web Worker の transfer 計測、IndexedDB の履歴、Web Audio のフィードバック音と組み合わせると、カメラ操作UI、空中ショートカット、レビューキュー、推論負荷に応じた自動フレーム間引きに発展できます。

The samples can collect frame number, motion delta, send/skip/result events, pseudo inference latency, thresholds, worker busy rate, gesture top score, streak, cooldown, and fired commands. Combined with real Hand Landmarker 21-point landmarks, world landmarks, handedness, Gesture Recognizer canned gestures, Object Detector boxes, Image Segmenter masks, Web Worker transfer metrics, IndexedDB history, and Web Audio feedback, they can grow into camera control UI, mid-air shortcuts, review queues, and inference-aware frame throttling.

制作に使えそうな技術メモ

Production note

静的HTMLの段階では `@mediapipe/tasks-vision@1.0.1/+esm` の dynamic import preflight だけを置き、実推論なしで worker 投入ポリシーを確認できるようにしました。本番化する時は main thread で `createImageBitmap(video)` を作り、worker に bitmap と `performance.now()` 由来の timestamp を transfer し、worker 内で `FilesetResolver.forVisionTasks()` と `HandLandmarker.createFromOptions()` を初期化します。処理後は公式 worker と同じく bitmap を close し、結果は landmarks 全体ではなく command に必要な軽量イベントへ先に畳むと UI が作りやすくなります。

At the static-HTML stage, the sample only performs a dynamic import preflight for `@mediapipe/tasks-vision@1.0.1/+esm`, so the frame-submission policy can be tuned without live inference. In production, create an `ImageBitmap` from the video on the main thread, transfer the bitmap and a `performance.now()`-based timestamp to a worker, and initialize `FilesetResolver.forVisionTasks()` plus `HandLandmarker.createFromOptions()` inside the worker. After processing, close the bitmap like the official worker and collapse full landmark results into lightweight command events for UI work.

試すならこれ

If you try one thing

`Hand Worker Frame Gate` を開き、`Start stream` で timeline を動かし、`Worker inference` を上げて busy skip が増えることを確認します。次に `Send threshold` を上げると low-motion skip が増え、motion の少ないフレームを送らない挙動が見えます。派生サンプルでは `Noisy preset` を押し、score threshold と連続一致数を厳しくした時に command 発火が抑えられることを確認します。

Open `Hand Worker Frame Gate`, press `Start stream`, and raise `Worker inference` to see busy skips increase. Then raise `Send threshold` to see low-motion frames dropped before submission. In the derivative sample, press `Noisy preset` to verify that stricter score thresholds and consecutive confirmations suppress command firing.
