注目事例と何が面白いか

Notable example and why it matters

今日の注目は、MediaPipe v1.0.0 の Web 向け release note を単なる更新一覧ではなく、実装前の triage board として扱うことです。IIFE bundles は build pipeline なしの検証や script tag fallback、Text Embedder の Gecko 対応は browser support、Privacy Notice は同意 UI、`.litertlm` と `disableRewinding` は Web LLM の model file / context policy、running mode cache は Vision task の IMAGE / VIDEO 切替テストに直結します。

Today's notable angle is treating the MediaPipe v1.0.0 Web release notes not as a passive changelog, but as a pre-implementation triage board. IIFE bundles map to buildless demos and script-tag fallback, Gecko support for Text Embedder maps to browser support, the Privacy Notice maps to consent UI, `.litertlm` and `disableRewinding` map to Web LLM model-file and context policies, and running-mode caching maps to IMAGE / VIDEO switching tests for Vision tasks.

制作に使えそうな技術メモ

Production note

導入時は本体 release と個別 JS package の version を分けて確認し、CDN path は `@mediapipe/tasks-vision@1.0.1/vision_bundle.mjs` のように pin します。IIFE と ESM の両方を使う場合は global export 名、WASM path、CORS、worker 内 import を別々に probe します。LLM Inference は maintenance-only の案内が出ているため、新規 Web LLM は LiteRT-LM への移行余地、`.task` / `.litertlm` の model file routing、WebGPU compatibility、long-context policy を先に決めるのが安全です。

For adoption, check the core release and individual JavaScript package versions separately, and pin CDN paths such as `@mediapipe/tasks-vision@1.0.1/vision_bundle.mjs`. If both IIFE and ESM are used, probe global export names, WASM paths, CORS, and worker imports separately. Since LLM Inference is documented as maintenance-only, new Web LLM work should first decide the LiteRT-LM migration path, `.task` / `.litertlm` model routing, WebGPU compatibility, and long-context policy.
