注目事例と何が面白いか

Notable example and why it matters

v1.1.0のrelease noteには、previewとstill captureのあいだでストリーム解像度が動的に変わるときのlandmark drift修正があります。興味深いのは、推論結果が同じ正規化座標でも、表示前にピクセル座標へ持ち込んだ状態を保持すると意味がずれる点です。本命はこの差を一画面で見せます。

The v1.1.0 release notes a drift fix across dynamic stream-resolution changes. The main probe visualizes why retaining display-pixel state can change a normalized landmark's meaning.

表現・インタラクションのアイデア

Expression and interaction idea

本命では動く合成landmarkをSD/HD入力へ切り替え、正規化座標で平滑化した緑と、ピクセル値をそのまま引き継いだ橙を比較します。派生ではポインタでletterbox内を指定し、表示面・ソースpixel・正規化結果・鏡像化の対応を読み出します。

The main compares normalized smoothing with carried-over pixel smoothing across SD/HD. The derivative maps pointer input through letterboxing, source pixels, normalized results, and mirroring.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

保存するなら映像そのものではなく、timestamp、入力width/height、正規化landmark、表示変換、結果年齢、drop回数を最小単位にします。Pose/Holistic/Hand Landmarker、CanvasまたはWebGL、ResizeObserver、Performance API、同意済み診断ログを組み合わせれば、回転・capture切替・縦長UIでの座標破綻を比較できます。

Persist timestamps, dimensions, normalized landmarks, display transforms, result age, and drop counts—not video. Combine Tasks, Canvas/WebGL, ResizeObserver, Performance API, and consented diagnostics.

制作に使えそうな技術メモ

Production note

平滑化は推論モデルが返す正規化座標か、入力フレーム座標系で行い、CSS pixelへの変換は最後に一度だけ行います。各結果にはsource size、timestamp、mirror、object-fit相当のcrop/letterbox情報を付けます。live streamでは全フレーム出力を前提にせず、最後の結果の年齢に上限を設けます。

Smooth in normalized or input-frame coordinates, converting to CSS pixels only at the end. Attach dimensions, timestamp, mirror, and crop/letterbox state; bound result age because live streams can drop frames.

俯瞰メモ

Bird's-eye memo

Web MLの見た目の安定性は、推論精度の問題だけではありません。入力の寸法、非同期結果の時刻、letterboxや鏡像の表示変換を独立した偶然にせず、同じ結果メタデータとして運ぶと、表示側のバグをモデルの揺れと取り違えにくくなります。

Visual stability is not only a model-accuracy problem. Carry dimensions, async time, letterboxing, and mirroring with each result so rendering bugs are not mistaken for model jitter.
