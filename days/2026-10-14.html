制作に使えそうな技術メモ

Production note

Retriever の結果を UI に出す前に、score 順だけでなく family / parent record の重複、privacy tier、説明 token 予算、引用範囲、chunk の overlap を別々に見ると、似た候補が上位を埋める問題を避けやすくなります。TextChunker の size / overlap は recall を上げますが、overlap が大きいほど同じ文脈が複数 hit しやすいので、duplicate cluster と parent-child 表示を同時に設計するのが良さそうです。

Before showing Retriever results in the UI, inspect not only score order but also family / parent-record duplication, privacy tier, explanation-token budget, citation ranges, and chunk overlap. This helps avoid near-identical candidates filling the top slots. Larger TextChunker size / overlap can improve recall, but higher overlap increases repeated context, so duplicate clusters and parent-child display should be designed together.
