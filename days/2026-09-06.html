注目事例と何が面白いか

Notable example and why it matters

今日の注目は Pose Landmarker の optional segmentation mask です。公式 Web guide は normalized landmarks、world landmarks、segmentation masks を分けて説明し、`outputSegmentationMasks` は default false の明示オプションです。面白いのは、姿勢推定の結果をただ線で描くだけでなく、人物マスクを出すか、どの confidence を満たした時だけ採用するか、canvas overlay を何ピクセル相当まで許すかを UI の設計問題として扱える点です。

Today's notable point is the Pose Landmarker optional segmentation mask. The official Web guide separates normalized landmarks, world landmarks, and segmentation masks, while `outputSegmentationMasks` is an explicit option that defaults to false. The interesting part is treating pose output not only as skeleton drawing, but as a UI decision: when to request a person mask, which confidence gates must pass, and how much canvas overlay work is acceptable.

表現・インタラクションのアイデア

Expression and interaction idea

本命サンプル `Pose Mask Budget Lab` は、合成した人物 skeleton と人物マスクを表示し、detection / presence / tracking の gate、mask resolution、mask alpha、`outputSegmentationMasks` の on/off を動かせます。timeline は accepted、mask drawn、dropped を分けて表示します。派生の `Pose Visibility Event Router` は、visibility gate、腕上げ角度、depth lean、confirm frames を使い、Pose のランドマーク結果を `right-arm-raise` や `lean-forward` のようなアプリイベントへ変換します。

The main sample, `Pose Mask Budget Lab`, displays a synthetic person skeleton and person mask while exposing detection, presence, tracking gates, mask resolution, mask alpha, and the `outputSegmentationMasks` toggle. Its timeline separates accepted frames, mask-drawn frames, and dropped frames. The derivative `Pose Visibility Event Router` uses a visibility gate, arm-raise angle, depth lean, and confirmation frames to convert pose landmarks into app events such as `right-arm-raise` or `lean-forward`.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

蓄積できるデータは、confidence gate、accepted/dropped frame、mask pixel estimate、overlay cost estimate、mask alpha、33点ランドマーク風の座標、visibility、world-depth 風の値、stable event、confirm streak です。これを実 Pose Landmarker の `PoseLandmarkerResult`、Image Segmenter のマスク合成、Gesture Recognizer の手の合図、Web Audio のフィードバック音、WebXR の身体方向 UI、IndexedDB の練習ログ、Worker の latency telemetry と組み合わせると、運動フォーム確認、立ち位置ガイド、カメラ前プレゼン操作、マスク付き身体エフェクト、省負荷な姿勢イベント検出へ発展できます。

The samples can accumulate confidence gates, accepted/dropped frames, mask pixel estimates, overlay cost estimates, mask alpha, synthetic 33-point-like landmark positions, visibility, world-depth-like values, stable events, and confirmation streaks. Combined with real `PoseLandmarkerResult`, Image Segmenter mask composition, Gesture Recognizer hand signs, Web Audio feedback, WebXR body-direction UI, IndexedDB practice logs, and worker latency telemetry, these can grow into exercise-form review, standing-position guidance, camera-based presentation controls, masked body effects, or low-cost pose-event detection.

制作に使えそうな技術メモ

Production note

本命 HTML は `@mediapipe/tasks-vision@1.0.1/+esm` の dynamic import preflight を持ち、実装時の CDN / module 読み込み確認に使えます。本番化では `FilesetResolver.forVisionTasks()`、`PoseLandmarker.createFromOptions()`、`pose_landmarker_lite/full/heavy.task`、`runningMode: "VIDEO"`、`outputSegmentationMasks` を接続し、video loop では `detectForVideo(video, timestamp)` の結果と描画を分離します。マスクは出せば便利ですが、ImageData / canvas / texture 変換のコストが出るため、低解像度の preview と高解像度の capture を分ける設計が現実的です。

The main HTML includes a dynamic import preflight for `@mediapipe/tasks-vision@1.0.1/+esm`, which helps verify CDN/module loading before real integration. For production, connect `FilesetResolver.forVisionTasks()`, `PoseLandmarker.createFromOptions()`, `pose_landmarker_lite/full/heavy.task`, `runningMode: "VIDEO"`, and `outputSegmentationMasks`; in a video loop, separate `detectForVideo(video, timestamp)` results from drawing. Masks are useful, but ImageData/canvas/texture conversion has cost, so separating low-resolution preview from high-resolution capture is practical.
