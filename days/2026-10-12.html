制作に使えそうな技術メモ

Production note

実装時は `recognizeForVideo()` のような同期 video inference を Worker 側で扱い、main thread では action readiness と説明文だけを受け取る形にすると扱いやすいです。`BaseOptions` の `modelAssetPath` と delegate、Task ごとの running mode、timestamp 単調性、結果の freshness TTL、risk 別の approval policy を別々にログ化すると、後段 Decision / Retrieval の誤作動を調整できます。

In production, keep synchronous video inference such as `recognizeForVideo()` in a worker and pass only action readiness plus short explanations back to the main thread. Logging `BaseOptions.modelAssetPath`, delegates, per-task running modes, timestamp monotonicity, result freshness TTL, and risk-specific approval policy separately makes downstream Decision / Retrieval behavior easier to tune.

試すならこれ

If you try one thing

`Decision Handoff Readiness Board` で Action risk を high にし、Decision threshold を上げると、同じ confidence でも fire から review / hold へ寄ります。`Retrieval Context Budget Router` では Privacy strictness を上げ、Context byte budget を下げると、face cue や大きな mask digest が compress / drop に寄り、検索へ渡す情報量が小さくなります。

In `Decision Handoff Readiness Board`, set action risk to high and raise the decision threshold to see the same confidence move from fire toward review / hold. In `Retrieval Context Budget Router`, raise privacy strictness and lower the context byte budget to push face cues and large mask digests toward compress / drop, reducing the information passed to retrieval.
