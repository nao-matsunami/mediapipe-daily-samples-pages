注目事例と何が面白いか

Notable example and why it matters

今日の注目は、生成系 text task を「要約が出る」だけで扱わず、入力長、token cap、出力形状、レビュー承認、privacy copy の境界を UI に出すことです。Text summarization guide は TLDR / KEYPOINTS と `max_num_tokens` を示し、MediaPipe v1.0.0 release notes は TextSummarizer / TextProofreader の追加と Web 側の更新を並べています。日次サンプルでは実モデルを呼ばず、モデル接続前に破綻しやすい運用面を触れる形にしました。

Today's notable angle is treating generated-text tasks as more than summary output: input length, token caps, output shape, review approval, and privacy-copy boundaries should be visible in the UI. The Text summarization guide exposes TLDR / KEYPOINTS and `max_num_tokens`, while MediaPipe v1.0.0 release notes place TextSummarizer / TextProofreader additions next to Web updates. The daily samples avoid calling a real model and instead make the fragile operational layer testable first.

表現・インタラクションのアイデア

Expression and interaction idea

本命サンプル `Text Summarizer Budget Planner` は、mode、max tokens、入力語数、device profile、圧縮率を動かし、推定 token、latency、memory、split 要否を表示します。派生の `Text Proofreader Revision Gate` は、proofreader 風の修正候補を grammar / meaning / privacy に分け、auto apply してよいものとレビューが必要なものを分離します。

The main sample, `Text Summarizer Budget Planner`, exposes mode, max tokens, input words, device profile, and compression ratio while showing estimated tokens, latency, memory, and whether splitting is needed. The derivative, `Text Proofreader Revision Gate`, separates proofreader-style suggestions into grammar, meaning, and privacy categories and distinguishes safe auto-apply edits from review-required changes.

Combined with Text Summarizer, TextProofreader, Text Classifier, Language Detector, Text Embedder, LiteRT-LM, IndexedDB, audit logs, document CMSs, and human review queues, they can form a pre-publication pipeline for on-device generated text.

制作に使えそうな技術メモ

Production note

実接続時は生成系 adapter を UI から切り離し、`mode` と `max_num_tokens` を job metadata として保存します。Web では LLM Inference API が maintenance-only とされているため、LiteRT-LM JavaScript、Tasks Text の将来更新、既存 tasks-text package の境界を分けます。privacy や consent を含む文面は、proofread 後でも auto publish せず、人間レビューを通すフラグを残します。

When wiring a real model, keep the generated-text adapter separate from the UI and save `mode` plus `max_num_tokens` as job metadata. On Web, because the LLM Inference API is marked maintenance-only, separate LiteRT-LM JavaScript, future Tasks Text updates, and the existing tasks-text package boundary. Copy that contains privacy or consent language should keep a human-review flag even after proofreading.
