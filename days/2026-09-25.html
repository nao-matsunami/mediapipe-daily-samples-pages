注目事例と何が面白いか

Notable example and why it matters

今日の注目は、Text Classifier を「テキストを入れるとラベルが返る」だけで終わらせず、同期 `classify()` を Web UI の待ち行列、処理予算、古い結果の拒否、ユーザー向け policy action へ接続することです。公式 API は TextClassifier、FilesetResolver、setOptions の入口を示し、公式サンプル worker は timestamp 付きで結果を返す構成を見せています。日次サンプルでは実モデルではなく、自作の分類シミュレータで運用面を先に触れるようにしました。

Today's notable angle is not stopping at text-in / label-out, but connecting synchronous `classify()` calls to a Web UI queue, processing budget, stale-result rejection, and user-facing policy actions. The official API documents TextClassifier, FilesetResolver, and setOptions, while the official sample worker shows timestamped result posting. The daily samples use an original classifier simulator so the operational surface can be tested before wiring a real model.

表現・インタラクションのアイデア

Expression and interaction idea

本命サンプル `Text Classifier Queue Guard` は、入力テキストを job として enqueue し、score threshold、maxResults、queue limit、budget per job を動かして、処理済み、stale、drop、over-budget を見ます。派生の `Text Policy Score Tuner` は分類 category score を allow / hold / review / block に変換し、privacy weight と ambiguity margin を触って、あいまいな分類を人間レビューへ戻す境界を確認します。

The main sample, `Text Classifier Queue Guard`, enqueues input text as jobs and exposes score threshold, maxResults, queue limit, and budget per job while showing processed, stale, dropped, and over-budget states. The derivative, `Text Policy Score Tuner`, maps category scores to allow / hold / review / block actions and lets privacy weight plus ambiguity margin move uncertain classifications back to human review.

制作に使えそうな技術メモ

Production note

実モデル接続時は `@mediapipe/tasks-text` と WASM path を pin し、`FilesetResolver.forTextTasks()` と `TextClassifier.createFromOptions()` の初期化を worker 内へ閉じ込めます。UI は classify の戻りを直接信じず、request id / timestamp / active id を照合して古い結果を捨てます。`setOptions()` で threshold や maxResults を変える場合は、すべての履歴を再分類するのではなく、現在表示中または未処理 job だけに絞るとコストを読みやすくできます。

When wiring the real model, pin `@mediapipe/tasks-text` and the WASM path, then keep `FilesetResolver.forTextTasks()` and `TextClassifier.createFromOptions()` inside a worker. The UI should not trust classify returns directly; compare request IDs, timestamps, and active IDs to reject old results. When changing threshold or maxResults through `setOptions()`, reclassify only the currently displayed or pending jobs instead of the entire history to keep costs understandable.
