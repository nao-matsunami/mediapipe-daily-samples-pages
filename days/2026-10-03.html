The main sample, `Tasks Bundle Worker Route Matrix`, compares ESM CDN, IIFE CDN, and npm Worker routes through app shell, CSP strictness, network jitter, WASM path health, worker load, offline mode, and cross-origin isolation. The derivative, `Privacy Metrics Consent Filter`, keeps input payloads local-only while routing runtime metrics to send / summarize / hold / drop based on consent mode, detail level, retention, and device stress.

制作に使えそうな技術メモ

Production note

実装時は `FilesetResolver.forVisionTasks()` の base path、CDN の `vision_bundle.mjs`、npm package から worker へ渡す import path、IIFE bundle の global namespace を別々に計測します。Vite では worker 内 import と asset copy の扱い、PWA では Service Worker cache と offline fallback、CSP では `script-src` / `worker-src` / `wasm-unsafe-eval` 相当の制約を UI に出すと調査が楽になります。Privacy Notice は入力が端末内で処理される説明と、performance / utilization metrics の説明を別のチェック項目に分けるのが実装上わかりやすいです。

In implementation, measure the `FilesetResolver.forVisionTasks()` base path, CDN `vision_bundle.mjs`, import paths passed from npm packages into workers, and IIFE bundle globals separately. With Vite, inspect worker imports and asset copying; with PWAs, inspect Service Worker cache and offline fallback; with CSP, surface constraints such as `script-src`, `worker-src`, and Wasm evaluation policy. For the Privacy Notice, it is clearer to separate the explanation that inputs are processed on device from performance / utilization metrics disclosure.
