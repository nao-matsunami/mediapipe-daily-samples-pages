Gesture Recognizer の結果を action gate で安定化する

Stabilizing Gesture Recognizer results with an action gate

Google AI Edge の Gesture Recognizer Web guide、GestureRecognizer JS API、公式 samples を確認し、カメラ入力の `recognizeForVideo()` と synthetic stream の両方で、enter / exit threshold、hold frames、cooldown による action gate を試せる自作 HTML サンプルを追加しました。

一覧代表サンプルを開く

今日の重要トピック

  1. Gesture Recognizer は手の gesture category、handedness、image landmarks、world landmarks を返し、ジェスチャーからアプリ機能を呼び出す用途に向いている。

    Gesture Recognizer returns gesture categories, handedness, image landmarks, and world landmarks, making it suitable for invoking application features from hand gestures.

  2. Web 版は `@mediapipe/tasks-vision` の `GestureRecognizer` を使い、静止画では `recognize()`、動画では `recognizeForVideo(videoFrame, timestamp)` を使う。

    On the web, `GestureRecognizer` from `@mediapipe/tasks-vision` uses `recognize()` for still images and `recognizeForVideo(videoFrame, timestamp)` for video.

  3. 公式 API は `setOptions()` で一部 option を更新でき、score threshold、label allowlist / denylist、running mode などを設計要素として扱える。

    The official API supports partial option updates through `setOptions()`, making score threshold, label allowlist / denylist, and running mode part of the design surface.

  4. 動画フレームでの recognition は同期的に UI thread をブロックし得るため、action 側では hold / cooldown / frame skipping を前提にしたほうが安全。

    Recognition on video frames can synchronously block the UI thread, so hold, cooldown, and frame skipping should be considered in the action layer.

  5. 生の gesture winner を action に直結すると誤発火しやすいので、enter threshold と exit threshold を分ける hysteresis が小さな UI でも効く。

    Mapping the raw gesture winner directly to actions causes false triggers; hysteresis with separate enter and exit thresholds helps even in small UI prototypes.

注目事例と何が面白いか

Notable example and why it matters

今日の注目は Gesture Recognizer が landmarks と gesture category を同時に返す点です。Hand Landmarker は 21 点の形を扱う土台でしたが、Gesture Recognizer は Thumb_Up や Victory のような意味ラベルを返すため、UI command やモード切り替えへ接続しやすくなります。ただし、スコアが一瞬上がっただけで action を発火すると誤操作になるので、認識結果からアクションまでの gate が重要です。

Today's notable point is that Gesture Recognizer returns both landmarks and gesture categories. Hand Landmarker gives the 21-point foundation, while Gesture Recognizer adds semantic labels such as Thumb_Up or Victory, making it easier to connect to UI commands or mode switches. However, firing an action when a score spikes for one frame causes false operations, so the gate between recognition result and action is important.

表現・インタラクションのアイデア

Expression and interaction idea

サンプルは Open_Palm、Closed_Fist、Pointing_Up、Thumb_Up、Victory、ILoveYou の synthetic score stream を生成し、棒グラフで生スコアと平滑化後の状態を見せます。さらに `Start Camera` で GestureRecognizer model と webcam を起動し、`recognizeForVideo()` の実スコアを同じ action gate に流し込めます。Enter threshold、Exit threshold、Hold frames、Cooldown frames を調整すると、同じ認識スコアでも action が発火したり保留されたりします。

The sample generates a synthetic score stream for Open_Palm, Closed_Fist, Pointing_Up, Thumb_Up, Victory, and ILoveYou, then visualizes raw and smoothed scores as bars. `Start Camera` also loads the GestureRecognizer model and webcam, feeding real `recognizeForVideo()` scores into the same action gate. Adjusting enter threshold, exit threshold, hold frames, and cooldown frames changes whether the same recognition score fires or waits.

制作に使えそうな技術メモ

Production note

Gesture Recognizer の出力は `gestures`、`handedness`、`landmarks`、`worldLandmarks` の配列として扱います。UI action へ使う時は winner category だけでなく score、handedness、前回状態、hold 時間を一緒に見るのが実用的です。`recognizeForVideo()` は同期処理なので、毎フレーム必ず呼ぶより、video timestamp の更新確認、低頻度推論、UI 側の補間、Web Worker 化を組み合わせる設計にした方が安定します。

Gesture Recognizer output should be treated as arrays of `gestures`, `handedness`, `landmarks`, and `worldLandmarks`. For UI actions, use not only the winning category but also score, handedness, previous state, and hold duration. Because `recognizeForVideo()` is synchronous, a stable design should combine video timestamp checks, lower-frequency inference, UI interpolation, and possibly Web Worker execution rather than calling it unconditionally every frame.
