注目事例と何が面白いか

Notable example and why it matters

今日の注目は、Face Detector を「顔があるか」だけでなく、後段の処理に渡す ROI gate として見ることです。公式 Web guide は `detect()` / `detectForVideo()` と同期実行の注意点を示し、task guide は short-range と full-range の BlazeFace 変種を整理しています。そこで本命サンプルでは、合成シーンまたはアップロード画像に対して short / full model、confidence、NMS、ROI margin、keypoint overlay を切り替え、実 Task が読み込める場合は MediaPipe Face Detector を呼び、読み込めない場合も合成 detection で同じ判断軸を確認できるようにしました。

Today's notable angle is treating Face Detector not only as a yes/no face detector but as an ROI gate for downstream tasks. The official Web guide shows `detect()` / `detectForVideo()` and the synchronous-call caveat, while the task guide organizes short-range and full-range BlazeFace variants. The main sample therefore switches short / full model, confidence, NMS, ROI margin, and keypoint overlays for a synthetic scene or uploaded image, calling MediaPipe Face Detector when the real task loads and keeping the same decision surface testable with synthetic detections otherwise.

Expression and interaction idea

The main sample overlays detection boxes, six keypoints, keep/drop decisions, and ROI margins on one canvas, showing how downstream crops change as confidence and NMS move. The derivative sample isolates the representative-face selection that would be useful next. Changing confidence cutoff, IoU NMS, ROI grow, and center bias changes which face becomes the hero ROI in multi-person frames.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

蓄積できるデータは、source image、model choice、confidence threshold、suppression threshold、raw detections、kept detections、box size、keypoint coordinates、ROI margin、representative face id、detect latency です。Face Landmarker に渡して blendshape や mesh の初期 ROI にしたり、Image Segmenter の人物マスクと合わせて顔だけ privacy mask を強めたり、Object Detector の person box と一致する顔だけ採用したりできます。WebRTC のローカル会議画面なら、顔 ROI の安定度を見て自動 framing や blur strength を決める材料にもなります。

The samples can accumulate source image, model choice, confidence threshold, suppression threshold, raw detections, kept detections, box size, keypoint coordinates, ROI margin, representative face id, and detection latency. These can initialize Face Landmarker for blendshapes or mesh, strengthen privacy masks only around faces when combined with Image Segmenter person masks, or keep only faces matched to Object Detector person boxes. In a local WebRTC meeting view, ROI stability can drive automatic framing or blur strength.

制作に使えそうな技術メモ

Production note

静的HTMLでは `@mediapipe/tasks-vision@0.10.22/+esm` と同 version の WASM path を dynamic import し、公式 README とサンプル実装で示される `blaze_face_short_range` / `blaze_face_full_range` の model URL を使いました。Face Detector の Web guide では `detect()` と `detectForVideo()` が同期実行で UI thread をブロックし得ると説明されているため、今日の自作サンプルでは IMAGE mode の最小確認に留め、camera loop は明日以降の Worker 実装課題として残しました。

The static HTML dynamically imports `@mediapipe/tasks-vision@0.10.22/+esm` and the matching WASM path, then uses the `blaze_face_short_range` / `blaze_face_full_range` model URLs shown by the official README and sample implementation. Because the Web guide explains that `detect()` and `detectForVideo()` can synchronously block the UI thread, today's original sample stays with the minimal IMAGE-mode check and leaves camera-loop Worker execution for a later entry.

試すならこれ

If you try one thing

まず `Face Detector Range Gate` を開き、Synthetic ready のまま confidence を下げて小さい顔が入るかを見ます。次に NMS を下げて重複 box が落ちる様子を確認し、ROI margin を増やして後段 crop がどれだけ広がるかを見ます。モデル取得が通る環境では Load Task を押して、short-range と full-range を切り替えて同じ入力の挙動差を確認します。派生の `Face Box NMS Tuner` では preset を `Group photo` にして center bias を上げると、最高 score だけではなく画面中心の顔を代表 ROI にする判断を試せます。

First open `Face Detector Range Gate`, keep Synthetic ready, and lower confidence to see whether smaller faces enter. Then lower NMS to watch overlapping boxes drop, and increase ROI margin to see how far downstream crops expand. When model loading works, press Load Task and switch between short-range and full-range for the same input. In the derivative `Face Box NMS Tuner`, choose `Group photo` and raise center bias to test selecting the central face as representative ROI instead of only using the highest score.

俯瞰メモ

Bird's-eye memo

8月後半の試作は gesture、segmenter、prompt UI など「入力をどう判断へ変換するか」に寄ってきました。Face Detector はさらに手前の ROI 生成を担うため、単独 task の結果だけでなく、後段 task の初期条件として見ると使いどころが増えます。今日の2本は、検出結果をそのまま描くだけでなく、どれを採用し、どれだけ余白を持たせ、どの face を代表にするかを小さく分解しました。

The late-August prototypes have moved toward how input becomes decisions: gestures, segmenters, and prompt UIs. Face Detector sits even earlier as an ROI generator, so it becomes more useful when treated as an initial condition for downstream tasks, not only as a standalone result. Today's two samples break down not just drawing detections, but which detections to keep, how much margin to give them, and which face becomes representative.

今日のミニ試作候補

Today's mini prototype candidate

採用した本命は `Face Detector Range Gate` です。実際に動く部分は、合成 face scene、upload image、short-range / full-range model 選択、MediaPipe Face Detector task load、confidence / NMS / ROI margin controls、6 keypoint overlay、synthetic fallback、検出採用リストです。次に足すなら Worker 内 `detectForVideo()`、camera freeze、Face Landmarker への crop handoff、privacy blur strength、box history export を追加します。派生試作は `Face Box NMS Tuner` で、レポート中の「次に足すなら」の代表 ROI 選択、NMS 閾値、center bias、余白調整を短時間で試せます。

The selected main prototype is `Face Detector Range Gate`. The working pieces are a synthetic face scene, uploaded images, short-range / full-range model selection, MediaPipe Face Detector task loading, confidence / NMS / ROI margin controls, six-keypoint overlays, synthetic fallback, and a detection keep list. Next additions should include Worker-side `detectForVideo()`, camera freeze, crop handoff to Face Landmarker, privacy blur strength, and box history export. The derivative prototype is `Face Box NMS Tuner`, which quickly tests representative ROI selection, NMS thresholds, center bias, and margin tuning listed as next additions in the report.
