注目事例と何が面白いか

Notable example and why it matters

v1.1.1 includes a C API for receiving Task Abseil logs, Flutter / Flutter Web host environments, and WASM updates. More important than receiving logs is letting the app decide what to retain, why, and who can delete it. Rather than list official demos, this turns that decision into original control surfaces.

表現・インタラクションのアイデア

Expression and interaction idea

本命 `Task Log Redaction Console` は、同意、座標の丸め幅、セッション上限を動かし、疑似 Task event が保存・丸め・遮断のどれになるかを即時に示します。派生 `WASM Warmup Route Planner` は download、compile、idle 余裕を変え、lazy / warmup / cache hit の最初の操作待ちを横並びにします。

The main `Task Log Redaction Console` changes consent, coordinate rounding, and session limit to show whether synthetic Task events are retained, rounded, or blocked. The derivative `WASM Warmup Route Planner` adjusts download, compile, and idle headroom to compare lazy, warmup, and cache-hit waits.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

価値がある記録は、Task 名、delegate、初期化・推論時間、匿名化済みエラーコード、同意 version、削除時刻、cache 状態です。生画像、全文 query、細かなランドマークを診断目的で混ぜないことが出発点になります。TaskRunner、Performance API、Resource Timing、IndexedDB、Web Worker、SemanticRetriever を組み合わせれば、端末内だけで原因を切り分ける支援面や、遅い回線では先読みを抑える適応 UI に発展します。

Useful records include Task name, delegate, initialization/inference time, anonymized error code, consent version, deletion time, and cache state. Do not mix raw images, full queries, or fine landmarks into diagnostics. Combining TaskRunner, Performance API, Resource Timing, IndexedDB, Web Workers, and SemanticRetriever can grow local diagnosis surfaces and adaptive low-bandwidth preloading.

制作に使えそうな技術メモ

Production note

ログ介入点では allowlist を先に作り、識別子・座標・free text を drop / round / hash のどれにするかを型ごとに固定します。保存上限と TTL を持たせ、エクスポート前にも確認を入れます。WASM は初回操作の直前に重い create を置かず、idle callback や明示ボタンで warmup を選択可能にします。実測は network、cache、CPU、delegate を分け、平均ではなく p50/p95 を残します。

At log interception, define an allowlist first and fix drop / round / hash treatment by type for identifiers, coordinates, and free text. Add retention limits and TTL, plus confirmation before export. Keep expensive WASM creation away from first action, and make warmup selectable through idle callbacks or a clear button. Measure network, cache, CPU, and delegate separately, retaining p50/p95 rather than only an average.

試すならこれ

If you try one thing

本命でまず同意なしのまま 6件バーストを押し、何も記録しない状態を見てから同意を許可に変えてください。座標丸めを 64px、上限を 2件にすると、最小限の診断へ絞る効果が見えます。派生では download を 900ms 以上、idle を 500ms 以上にして warmup が効く境目を比較します。

In the main sample, burst six events with consent off, then enable it. Set coordinate rounding to 64px and the limit to two events to see minimal diagnostics. In the derivative, set download above 900ms and idle above 500ms to compare the warmup boundary.

俯瞰メモ

Bird's-eye memo
