今日の重要トピック

  1. Gesture Recognizer Web guide は、リアルタイムの手ジェスチャー認識に加えて hand landmarks も返すため、単なる分類結果ではなく位置つきコマンド入力として扱える。

    The Gesture Recognizer Web guide returns hand landmarks along with real-time gesture recognition, making it useful as positioned command input rather than only a classifier.

  2. Task overview / Web guide では、出力が gesture categories、handedness、image landmarks、world landmarks を含むことが示されており、左右手や奥行きを含む意図判定に展開できる。

    The task overview and Web guide describe outputs that include gesture categories, handedness, image landmarks, and world landmarks, which can support intent decisions involving left/right hands and depth.

  3. `recognize()` と `recognizeForVideo()` は実行モードに依存し、動画フレーム処理では timestamp を渡す API になっている。

    `recognize()` and `recognizeForVideo()` depend on the running mode, and video processing uses an API that accepts a frame timestamp.

  4. Web guide は `recognize()` / `recognizeForVideo()` が同期実行で UI thread をブロックし得ると明記しているため、常時カメラ処理では Worker 化が実装上の重要ポイントになる。

    The Web guide states that `recognize()` / `recognizeForVideo()` run synchronously and can block the UI thread, so Worker execution is important for continuous camera loops.

  5. 公式 mediapipe-samples-web の Gesture Recognizer 実装は confidence sliders、`numHands`、worker、公式モデルURLを持ち、今日の最小試作ではその後段の command routing に焦点を当てた。

    The official mediapipe-samples-web Gesture Recognizer implementation includes confidence sliders, `numHands`, a worker, and the official model URL; today's original sample focuses on command routing after that result layer.

注目事例と何が面白いか

Notable example and why it matters

今日の注目は Gesture Recognizer を「手の形ラベルを出す部品」ではなく、「ユーザーが意図して出した操作候補を返す部品」として扱える点です。Google AI Edge の Web guide は gesture recognition result と hand landmarks を返すことを示し、task guide は handedness、image landmarks、world landmarks まで含む出力を説明しています。そこで本命サンプルでは、Open_Palm、Closed_Fist、Pointing_Up、Thumb_Up、Victory、ILoveYou をそのまま表示せず、しきい値、保持フレーム、クールダウンを通して presenter / kiosk / capture の操作語彙へ変換しました。

Today's notable point is treating Gesture Recognizer not as a hand-shape labeler but as a component that returns candidate actions intentionally made by the user. The Google AI Edge Web guide shows gesture recognition results and hand landmarks, while the task guide describes outputs including handedness, image landmarks, and world landmarks. The main sample therefore does not simply display Open_Palm, Closed_Fist, Pointing_Up, Thumb_Up, Victory, and ILoveYou; it routes them through thresholds, hold frames, and cooldown into presenter / kiosk / capture command vocabularies.

表現・インタラクションのアイデア

Expression and interaction idea

本命サンプルは、カメラと公式 Gesture Recognizer task が使える環境では実モデルを読み、`recognizeForVideo()` の結果から gesture category を拾ってコマンドに変換します。使えない環境でも合成 gesture stream が走るため、ルータの enter threshold、release threshold、hold frames、cooldown を即座に検証できます。派生サンプルは、左手を mode key、右手を action key として扱い、左右の score と同期ウィンドウを満たした時だけ chord command を確定します。

The main sample loads the real Gesture Recognizer task when camera and model access are available, then converts `recognizeForVideo()` gesture categories into commands. When that is unavailable, a synthetic gesture stream still runs so the router's enter threshold, release threshold, hold frames, and cooldown can be tested immediately. The derivative sample treats the left hand as a mode key and the right hand as an action key, confirming a chord command only when both scores and the sync window are satisfied.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

蓄積できるデータは、top gesture、score、handedness、hold frames、active command、scenario、cooldown、latency、21点 landmarks、左右handの同期差です。IndexedDB に保存すれば、ユーザーごとの誤発火しやすいgestureや、デバイスごとの latency を分析できます。Web Audio と組み合わせると操作確定音を返せます。world landmarks を使えば、手が近すぎる時は無効化する、奥行きで hover / press を分ける、といった発展が可能です。Text Classifier や LLM Inference と組み合わせれば、手ジェスチャーで候補を選び、テキストAIでその操作文脈を補うUIにもできます。

The samples can accumulate top gesture, score, handedness, hold frames, active command, scenario, cooldown, latency, 21-point landmarks, and left/right hand sync offset. Stored in IndexedDB, this can reveal gestures that misfire per user and latency by device. With Web Audio it can return action confirmation tones. With world landmarks it can reject hands that are too close or separate hover from press by depth. Combined with Text Classifier or LLM Inference, hand gestures can select options while text AI fills in the operation context.

制作に使えそうな技術メモ

Production note

静的HTMLでは `@mediapipe/tasks-vision@0.10.22/+esm` を dynamic import し、`FilesetResolver.forVisionTasks()` と公式 gesture_recognizer task URL を使いました。`GestureRecognizer.createFromOptions()` では `runningMode: "VIDEO"`、`numHands: 2`、hand detection / presence / tracking confidence を指定しています。Web guide の注意どおり `recognizeForVideo()` は同期処理なので、実運用では official samples のように worker へ移し、main thread には command event と描画用の軽い状態だけを渡すのがよいです。

The static HTML dynamically imports `@mediapipe/tasks-vision@0.10.22/+esm`, then uses `FilesetResolver.forVisionTasks()` and the official gesture_recognizer task URL. `GestureRecognizer.createFromOptions()` sets `runningMode: "VIDEO"`, `numHands: 2`, and hand detection / presence / tracking confidence. As the Web guide warns, `recognizeForVideo()` is synchronous, so production code should move it into a worker like the official samples and send only command events plus lightweight render state to the main thread.

The selected main prototype is `Gesture Command Router`. The working pieces are loading the official Gesture Recognizer task, camera or synthetic gesture stream, gesture score smoothing, enter / release threshold, hold frames, cooldown, scenario-specific command mapping, and cue logs. Next additions should include Worker-side `recognizeForVideo()`, `worldLandmarks` depth filtering, JSONL export, Web Audio confirmation, and gesture allowlist / denylist controls. The derivative prototype is `Two Hand Chord Resolver`, which turns the two-hand chord idea from the report into a small working form and tests sync decisions between a left-hand mode key and right-hand action key.
