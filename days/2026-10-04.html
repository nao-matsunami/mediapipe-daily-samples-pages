注目事例と何が面白いか

Notable example and why it matters

今日の注目は、MediaPipe LLM Inference API が maintenance-only になり、Web project は LiteRT-LM JavaScript API への移行を推奨されている点です。これは単なる package 差し替えではなく、WebGPU、モデル形式、prompt 長、メモリ、offline/privacy 要件を最初に判定する UI を持つと、実モデル接続前に失敗条件をかなり減らせるという話です。Studio の custom model 導線も同じで、metadata と入出力 shape の前処理をアプリ内に置く価値があります。

Today's notable point is that the MediaPipe LLM Inference API is in maintenance-only mode and Web projects are encouraged to migrate to the LiteRT-LM JavaScript API. This is not just a package swap: a first-run UI that checks WebGPU, model format, prompt length, memory, and offline/privacy requirements can remove many failure cases before real model hookup. The same applies to the Studio custom-model path, where metadata and input/output shape preflight belong in the app.

表現・インタラクションのアイデア

Expression and interaction idea

本命サンプル `LiteRT-LM Device Fit Planner` は LiteRT-LM small、Gemma 3n task、legacy LLM Inference を候補にして、Use case、Device memory、Prompt tokens、WebGPU score、Privacy need、offline toggle を動かすと ship / pilot / defer が変わります。派生の `Custom Model Metadata Gate` は Studio 風に task type と model readiness を選び、metadata、tensor match、label quality、calibration coverage、custom input smoke test で pass / review / block を出します。

The main sample, `LiteRT-LM Device Fit Planner`, compares LiteRT-LM small, Gemma 3n task, and legacy LLM Inference. Changing use case, device memory, prompt tokens, WebGPU score, privacy need, and offline mode changes the ship / pilot / defer decision. The derivative, `Custom Model Metadata Gate`, follows a Studio-like custom model flow and routes metadata, tensor match, label quality, calibration coverage, and custom input smoke tests to pass / review / block.

制作に使えそうな技術メモ

Production note

実装時は `navigator.gpu` の有無だけでなく adapter request の失敗、GPU delegate fallback、first-token latency、modelAssetPath / modelAssetBuffer の読み込み経路、`.task` / `.litertlm` の形式、prompt token cap を別々に記録します。custom model では TFLite metadata、input normalization、output tensor name、label map locale、score threshold の調整幅、custom input smoke test を最初に出すと、Studio で試せるものを自前アプリに入れる前の gate として使えます。

In implementation, track not only whether `navigator.gpu` exists but also adapter request failures, GPU delegate fallback, first-token latency, modelAssetPath / modelAssetBuffer loading routes, `.task` / `.litertlm` format, and prompt token caps separately. For custom models, surfacing TFLite metadata, input normalization, output tensor names, label-map locale, score-threshold range, and a custom-input smoke test provides a gate before moving Studio-tested models into a real app.

In the derivative, set task type to Object Detector, lower label quality and calibration coverage, then toggle custom input to see which checks cannot pass on metadata alone.
