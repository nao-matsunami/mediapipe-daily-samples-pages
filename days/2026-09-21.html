注目事例と何が面白いか

Notable example and why it matters

今日の注目は、Language Detector を「言語を当てる demo」ではなく、UI routing の前段として扱うことです。候補言語の信頼度が高ければローカライズ済み UI に直接流し、低ければ翻訳待ちや人手レビューへ回す。`maxResults` は曖昧さをどこまで表示するか、`scoreThreshold` は自動処理の境界、allowlist / denylist は市場やサポート体制の制約として効きます。

Today's angle is treating Language Detector not as a simple language-guessing demo, but as a front end to UI routing. High-confidence candidates go directly to localized UI, while low-confidence text moves to translation or human review. `maxResults` controls how much ambiguity is shown, `scoreThreshold` sets the automation boundary, and allowlist / denylist settings encode market or support constraints.

Expression and interaction idea

本命サンプル `Language Detector Confidence Router` は、入力文、score threshold、max results、allowlist profile、ambiguity boost を動かすと候補言語と route が更新されます。派生の `Language Policy Allowlist Playground` は、allowlist / denylist / no filter、market preset、confidence floor、novelty penalty を切り替え、どの問い合わせが direct、low-confidence、filtered、config-error になるかを見せます。

The main sample, `Language Detector Confidence Router`, updates candidate languages and routes as you adjust input text, score threshold, max results, allowlist profile, and ambiguity boost. The derivative, `Language Policy Allowlist Playground`, switches allowlist / denylist / no-filter modes, market presets, confidence floor, and novelty penalty to show which messages become direct, low-confidence, filtered, or config-error routes.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

蓄積できるデータは入力テキスト、候補言語、score、threshold、maxResults、allowlist / denylist mode、route、review count、market preset、設定衝突です。Language Detector と Text Classifier、Text Embedder、LLM summarizer、翻訳 API、IndexedDB、support inbox、Privacy Notice copy、Playwright smoke test を組み合わせると、ブラウザ内で個人情報を外へ出さずに一次 routing を行い、必要な時だけ翻訳や人手確認へ進む軽量な多言語 triage にできます。

The samples can collect input text, candidate languages, scores, thresholds, maxResults, allowlist / denylist mode, route, review count, market preset, and configuration conflicts. Combined with Language Detector, Text Classifier, Text Embedder, an LLM summarizer, translation APIs, IndexedDB, support inboxes, Privacy Notice copy, and Playwright smoke tests, this becomes a lightweight multilingual triage layer that routes locally in the browser before escalating to translation or human review.

制作に使えそうな技術メモ

Production note

実装時は `@mediapipe/tasks-text` の version と CDN path を pin し、`FilesetResolver.forTextTasks()` の WASM path と modelAssetPath を別々に確認します。`scoreThreshold` は model metadata の既定 threshold を上書きできるため、UI の自動応答や翻訳起動の境界として扱います。`categoryAllowlist` と `categoryDenylist` は同時指定できないので、設定画面では片方を選ぶ segmented control にし、保存前に conflict guard を入れるのが安全です。

For production, pin the `@mediapipe/tasks-text` version and CDN path, and check the `FilesetResolver.forTextTasks()` WASM path separately from the modelAssetPath. Since `scoreThreshold` can override the model metadata threshold, it can serve as the boundary for automated UI responses or translation launch. Because `categoryAllowlist` and `categoryDenylist` are mutually exclusive, configuration UI should choose one mode with a segmented control and validate conflicts before saving.

試すならこれ

If you try one thing

`Language Detector Confidence Router` で Preset を `short ambiguous` にし、Score threshold を 0.70 以上へ上げると、人手レビューへ落ちる状態が見えます。Allowlist を `ja,en,es` にすると候補の出方も変わります。派生サンプルでは Policy mode を `allowlist`、Market preset を `Japan launch` にしてから Toggle conflict を押すと、allowlist と denylist の同時指定を禁止すべき理由が `config-error` として見えます。

In `Language Detector Confidence Router`, switch Preset to `short ambiguous` and raise Score threshold above 0.70 to see the human-review route. Changing Allowlist to `ja,en,es` also changes the candidate set. In the derivative sample, set Policy mode to `allowlist`, Market preset to `Japan launch`, then press Toggle conflict to see why simultaneous allowlist and denylist settings should surface as `config-error`.
