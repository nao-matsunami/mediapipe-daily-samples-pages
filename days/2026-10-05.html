注目事例と何が面白いか

Notable example and why it matters

今日の注目は、Gesture Recognizer と Hand Landmarker の Web guide がどちらも camera / video frame の同期推論による UI thread blocking に触れている点です。公式デモはすぐ試せる入口として有用ですが、実アプリでは permission、secure context、解像度、FPS、confidence threshold、worker handoff を起動前に見せるだけで、失敗時の体験をかなり整えられます。

Today's notable point is that both the Gesture Recognizer and Hand Landmarker Web guides call out UI-thread blocking from synchronous camera / video-frame inference. Official demos are useful entry points, but a real app benefits from showing permission, secure context, resolution, FPS, confidence thresholds, and worker handoff before startup.

表現・インタラクションのアイデア

Expression and interaction idea

本命サンプル `Camera Permission Frame Budget Lab` は task、resolution、FPS、inference cost、tracking confidence を動かすと direct / throttle / worker の推奨が変わり、合成 camera canvas と timeline で skip / block を見せます。派生の `Camera Constraint Fallback Router` は facingMode、width、height、FPS、NotAllowedError / NotFoundError / OverconstrainedError / NotReadableError を選ぶと、requested から balanced、landmark safe、image mode へ落ちる ladder が更新されます。

The main sample, `Camera Permission Frame Budget Lab`, changes direct / throttle / worker recommendations as task, resolution, FPS, inference cost, and tracking confidence are adjusted, with a synthetic camera canvas and skip / block timeline. The derivative, `Camera Constraint Fallback Router`, updates a ladder from requested to balanced, landmark safe, and image mode based on facingMode, width, height, FPS, and simulated NotAllowedError / NotFoundError / OverconstrainedError / NotReadableError.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

蓄積できるデータは permission state、secure context、camera constraints、target FPS、resolution、estimated sync inference cost、tracking confidence、reacquire risk、fallback route、error type、worker recommendation です。MediaPipe Hand Landmarker、Gesture Recognizer、Holistic Landmarker、Object Detector、PerformanceObserver、Long Task API、Web Worker、OffscreenCanvas、IndexedDB、privacy notice version と組み合わせると、端末ごとに camera 起動条件と worker / throttle policy を保存できます。

The samples can accumulate permission state, secure context, camera constraints, target FPS, resolution, estimated synchronous inference cost, tracking confidence, reacquire risk, fallback route, error type, and worker recommendations. Combined with MediaPipe Hand Landmarker, Gesture Recognizer, Holistic Landmarker, Object Detector, PerformanceObserver, the Long Task API, Web Workers, OffscreenCanvas, IndexedDB, and privacy notice versions, an app can store camera startup and worker / throttle policy per device.

制作に使えそうな技術メモ

Production note

実装時は `navigator.permissions.query({name: 'camera'})` が使えない browser もある前提で、permission query、明示的な getUserMedia request、error name、constraints fallback を分けて記録します。MediaPipe Tasks 側では IMAGE / VIDEO running mode の切り替え、`setOptions()` のタイミング、duplicate timestamp 回避、`detectForVideo()` / `recognizeForVideo()` の同期コスト、worker handoff の queue depth を別々に見ると運用しやすいです。

In implementation, treat permission queries, explicit getUserMedia requests, error names, and constraint fallback as separate records because `navigator.permissions.query({name: 'camera'})` is not uniformly available. On the MediaPipe Tasks side, track IMAGE / VIDEO running mode changes, `setOptions()` timing, duplicate timestamp avoidance, synchronous `detectForVideo()` / `recognizeForVideo()` cost, and worker-handoff queue depth separately.
