  1. Hand Landmarker Web guide は `minHandPresenceConfidence` を下回ると palm detection model が呼ばれ、`minTrackingConfidence` は前後フレームの手の bounding box IoU 閾値として使われると説明している。

    The Hand Landmarker Web guide explains that `minHandPresenceConfidence` below threshold triggers the palm detection model, while `minTrackingConfidence` is used as a hand bounding box IoU threshold across frames.

  2. `detect()` / `detectForVideo()` は同期実行で UI thread をブロックし得るため、カメラ動画では Worker 化、フレーム間引き、予算メーターを先に設計する価値がある。

    `detect()` and `detectForVideo()` run synchronously and can block the UI thread, so camera video benefits from worker boundaries, frame skipping, and budget meters.

  3. Hand Landmarker の出力は 21 landmarks、world landmarks、handedness を含むため、同じ結果から描画、操作、奥行きゲート、安定化ログを作れる。

    Hand Landmarker output includes 21 landmarks, world landmarks, and handedness, enabling drawing, interaction, depth gating, and stabilization logs from one result.

    Gesture Recognizer returns both hand landmarks and gesture categories, making the Hand Landmarker tracking and dwell design reusable for command UIs.

注目事例と何が面白いか

Notable example and why it matters

今日の注目は、Hand Landmarker Web guide が presence / tracking confidence と再検出の関係をかなり実装寄りに説明している点です。Video mode では、手の存在確信度が下がる、または tracking confidence が閾値を下回ると、軽量trackingだけで次フレームへ進むのではなく palm detector に戻る設計になります。これは精度だけの話ではなく、再検出が増えるほど同期推論のフレーム予算を圧迫するというUI設計上の問題でもあります。

Today's notable point is that the Hand Landmarker Web guide describes the relationship between presence / tracking confidence and reacquisition in implementation-oriented terms. In video mode, when hand presence or tracking confidence falls below threshold, the pipeline returns to the palm detector instead of only continuing lightweight tracking. This is not only an accuracy issue; more reacquisition can consume more of the synchronous inference frame budget.

表現・インタラクションのアイデア

Expression and interaction idea

本命サンプル `Hand Reacquire Threshold Tuner` は、実モデルをロードできるボタンを持ちつつ、カメラやCDNが使えない場合も疑似スコア列で動きます。presence threshold、tracking threshold、frame budget を触ると、同じ手の状態でも「track existing hand」と「reacquire palm detector」の判断が切り替わり、latency meter とログで負荷の見え方が変わります。派生の `Hand Depth Dwell Gate` は、次に足すならと考えた z-depth 操作のうち、近距離に一定時間留まったら一度だけ発火するUI部品だけを切り出しました。

The main sample, `Hand Reacquire Threshold Tuner`, can load the real model but also runs with simulated score streams when camera or CDN access is unavailable. Changing presence threshold, tracking threshold, and frame budget flips the same hand state between `track existing hand` and `reacquire palm detector`, while the latency meter and log show the cost. The derivative `Hand Depth Dwell Gate` isolates one next-step idea: fire once when a z-depth hand signal stays in the near zone for a dwell period.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

蓄積できるデータは、presence score、tracking score、閾値、reacquire count、frame latency、budget ratio、source、z depth、near-zone entry/exit、dwell progress、command fire log です。これを Hand Landmarker の landmarks/world landmarks、Gesture Recognizer の category score、PerformanceObserver、Worker postMessage latency、camera resolution selector、localStorage の session replay と組み合わせると、Web ML 操作UIの「認識できたか」ではなく「操作として安定したか」を短いログで比較できます。

The samples can accumulate presence score, tracking score, thresholds, reacquire count, frame latency, budget ratio, source, z depth, near-zone entry/exit, dwell progress, and command fire logs. Combined with Hand Landmarker landmarks/world landmarks, Gesture Recognizer category score, PerformanceObserver, worker postMessage latency, camera resolution selection, and localStorage session replay, they can compare whether a Web ML control is stable as an interaction, not just whether recognition worked.

制作に使えそうな技術メモ

Production note

静的HTMLでは `@mediapipe/tasks-vision@1.0.1/+esm` を dynamic import し、`FilesetResolver.forVisionTasks()` に同じversionの wasm path を渡しました。モデルは hosted `hand_landmarker.task` を使い、`HandLandmarker.createFromOptions()` で `runningMode: "VIDEO"`、`numHands: 2`、presence / tracking 閾値を指定します。閾値スライダー変更時は `setOptions()` で再設定し、実推論が使えない場合も同じUIが疑似スコアに対して動くようにしました。

The static HTML dynamically imports `@mediapipe/tasks-vision@1.0.1/+esm` and passes a same-version wasm path to `FilesetResolver.forVisionTasks()`. It uses the hosted `hand_landmarker.task` and configures `HandLandmarker.createFromOptions()` with `runningMode: "VIDEO"`, `numHands: 2`, and presence / tracking thresholds. Slider changes call `setOptions()`, while the same UI also runs against simulated scores when real inference is unavailable.

試すならこれ

If you try one thing

`Hand Reacquire Threshold Tuner` を開き、まず model なしで scenario を `jitter / partial occlusion` にして `Start loop` を押します。presence / tracking threshold を上げるほど reacquire count が増え、latency meter が予算を食う前提に変わります。次に `lost then reacquire` を選ぶと、一時的な手の消失に対して閾値が厳しすぎるかを確認できます。派生サンプルでは `Play pattern` を押し、near threshold と dwell を変えて意図しない発火を抑えられるかを見ます。

Open `Hand Reacquire Threshold Tuner`, first choose `jitter / partial occlusion` without loading the model, and press `Start loop`. Raising presence / tracking thresholds increases reacquire count and changes the latency meter assumption. Then choose `lost then reacquire` to see whether thresholds are too strict for temporary hand loss. In the derivative sample, press `Play pattern` and tune near threshold plus dwell to suppress accidental firing.
