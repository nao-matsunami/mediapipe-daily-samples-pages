注目事例と何が面白いか

Notable example and why it matters

今日の注目は、MediaPipe Tasks の Web アプリで複数の Vision Task を同時に使いたくなった時、実際には「全部を毎フレーム実行する」よりも、どの Task をいつ走らせ、古い結果をどう表示するかが体験を左右する点です。公式 guide と API reference は video mode と同期応答の前提を示しているため、サンプルでは実モデル読み込みではなくレーン配分と overlay 鮮度を独立して可視化しました。

Today's notable point is that when a Web app wants to use multiple MediaPipe Vision Tasks, the experience is shaped less by running everything every frame and more by deciding which task runs when and how stale results remain visible. The official guides and API reference establish video mode and synchronous responses, so these samples isolate lane scheduling and overlay freshness instead of loading real models.

制作に使えそうな技術メモ

Production note

`recognizeForVideo()` や `detectForVideo()` を同じ frame callback 内で複数回呼ぶ場合、推論時間だけでなく overlay 描画、結果の有効期限、次フレームの入力取得まで含めて予算化します。最低限、Task ごとの lastRun timestamp、maxAge、confidence、UI action を持たせると、古い結果を残すべきか消すべきかを一貫して判断できます。

When calling `recognizeForVideo()` or `detectForVideo()` multiple times inside the same frame callback, budget not only inference time but also overlay drawing, result expiration, and acquisition of the next input frame. At minimum, keeping lastRun timestamps, maxAge, confidence, and UI action per task makes stale-result display decisions consistent.
