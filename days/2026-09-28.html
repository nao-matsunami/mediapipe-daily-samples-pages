注目事例と何が面白いか

Notable example and why it matters

今日の注目は Object Detector の Web guide にある score threshold、max results、allowlist / denylist を、検出結果そのものではなくイベント化の手前の安定化レイヤーとして扱うことです。公式 demo は検出をすぐ可視化しますが、実アプリでは同じ ROI が連続発火したり、低スコア候補が review queue を汚したりします。そこで本命サンプルは synthetic detection stream を使い、emit / review / drop の境界を操作できるようにしました。

Today's notable angle is treating Object Detector Web guide options such as score threshold, max results, allowlist, and denylist as a stabilization layer before detections become events. Official demos visualize detections directly, but real apps can repeatedly fire the same ROI or pollute review queues with low-score candidates. The main sample therefore uses a synthetic detection stream and exposes the emit / review / drop boundary.

制作に使えそうな技術メモ

Production note

実接続時は `ObjectDetector.detectForVideo(video, timestampMs)` の timestamp をイベント ID に含め、同じ frame から作った policy 結果だけをまとめます。`maxResults` は UI 表示数ではなく後段キューの上限にも効くため、review queue と analytics channel で別々に持つのが安全です。allowlist と denylist は同時指定不可なので、設定 UI では conflict guard を置きます。

When wiring a real model, include the `ObjectDetector.detectForVideo(video, timestampMs)` timestamp in event IDs and group policy results made from the same frame. `maxResults` affects more than UI display count; it can also limit downstream queues, so review queues and analytics channels should have separate caps. Since allowlists and denylists are mutually exclusive, the settings UI needs a conflict guard.
