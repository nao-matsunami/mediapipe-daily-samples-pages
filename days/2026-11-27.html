表現・インタラクションのアイデア

Expression and interaction idea

本命はWorkerのready前では最新フレームだけを保留し、古いepochの応答を描画しないリレーです。派生はカテゴリ値を意味色へ写し、しきい値と見た目の不透明度を独立に触れるマスク実験です。待ち状態と色付けの判断を、黒箱にしないインタラクションにします。

The main keeps only the newest frame before worker readiness; the derivative separates semantic palette policy from threshold and opacity.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

frame ID、worker epoch、asset読込時間、転送サイズ、結果年齢、カテゴリごとの面積と採用しきい値をイベント列として残せます。Performance API、Web Worker、OffscreenCanvas、ImageBitmap、MediaStreamTrack、IndexedDBと結べば、端末別の遅延や描画負荷を比較できます。将来は手・姿勢ランドマークをマスクの意味色に重ね、音やXRの遮蔽にも展開できます。

Frame lineage, worker epochs, asset timing, and category area can join performance traces, worker graphics, local history, landmarks, audio, and XR.

制作に使えそうな技術メモ

Production note

実装ではTask asset URLをWorkerで解決できるかビルド時に確認し、Taskごとにepochと終了手順を持たせます。VideoFrameやImageBitmapは転送後の所有権を明確にし、描画後は保持しません。カテゴリマスクは推論値、しきい値、配色、合成不透明度を別々の設定にして、GPU/CPU経路とコピー回数を計測します。

Resolve task assets in workers at build time, track epochs and cleanup, transfer image ownership explicitly, and separate mask semantics from display policy.

俯瞰メモ

Bird's-eye memo

Web MLの体験差は、モデルが返す値そのものより、結果がいつ・どの文脈で画面へ採用されるかに現れます。Worker、asset、GPU出力を導入するときほど、入力の所有、結果の新しさ、色の意味を小さな契約として可視化する価値があります。

Web ML quality depends on when and in which context results are accepted; workers and GPU paths need visible ownership, freshness, and semantic contracts.
