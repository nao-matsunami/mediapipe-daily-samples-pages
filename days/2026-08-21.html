今日の重要トピック

  1. MediaPipe Tasks JavaScript の FilesetResolver は Task API に必要な fileset を解決し、SIMD 対応環境では SIMD 用ファイルを選ぶため、モデル前の WASM 配置確認が重要になる。

    MediaPipe Tasks JavaScript FilesetResolver resolves the filesets required by Task APIs and selects SIMD files when supported, so WASM placement should be checked before model loading.

  2. tasks-vision package は Face / Hand / Pose / Object などの ready-made Vision Task と DrawingUtils を提供し、最短で機能を作る入口になる。

    The tasks-vision package provides ready-made Vision Tasks such as Face, Hand, Pose, and Object tasks plus DrawingUtils, making it the shortest path to feature work.

  3. LiteRT.js は WebAssembly の CPU 実行に加え、WebGPU と実験的な WebNN を Web 向けアクセラレーションとして扱い、独自 `.tflite` モデルの実行経路になる。

    LiteRT.js supports CPU execution through WebAssembly as well as WebGPU and experimental WebNN acceleration, making it the Web path for custom `.tflite` models.

  4. Google AI Edge は MediaPipe を ready-made Task、LiteRT-LM を on-device LLM、LiteRT を custom model deployment として位置づけており、用途別の振り分けが設計上の第一歩になる。

    Google AI Edge positions MediaPipe as ready-made Tasks, LiteRT-LM as on-device LLM, and LiteRT as custom model deployment, so routing by use case is the first design step.

  5. 公式 mediapipe-samples-web は実タスク出力の参考になるが、今日の公開カードは外部デモではなく、このワークスペースで作った初期化診断サンプルに限定した。

    The official mediapipe-samples-web project is useful for real task-output reference, but today's public card centers only on the initialization diagnostic sample created in this workspace.

注目事例と何が面白いか

Notable example and why it matters

今日の注目は、検出や分類の結果ではなく、結果が出る前の初期化判断です。MediaPipe Tasks は `FilesetResolver` により Task 用 WASM fileset を解決し、LiteRT.js は `loadLiteRt()` と `loadAndCompile()` で `.tflite` モデルを WebGPU / WebNN / WASM に流します。自作サンプルでは、ブラウザがどちらの入口に向いているかをクリック一つで測り、FPS とモデルサイズの圧力を加えて route recommendation として見せます。

Today's notable angle is the initialization decision before detection or classification output exists. MediaPipe Tasks resolves Task-specific WASM filesets through `FilesetResolver`, while LiteRT.js routes `.tflite` models through `loadLiteRt()` and `loadAndCompile()` toward WebGPU, WebNN, or WASM. The original sample measures which entry point the browser is ready for and adds FPS and model-size pressure to show a route recommendation.

制作に使えそうな技術メモ

Production note

MediaPipe Tasks は ready-made な API で最短に進められますが、WASM fileset の公開パス、SIMD availability、delegate、UI thread の詰まりを先に見ておくと事故が減ります。LiteRT.js は独自 `.tflite` と WebGPU / WebNN を扱える一方で、モデル変換、pre/post process、WASM 配置、WebGPU 非対応時の fallback が制作側の責任になります。今日のサンプルは、実モデルを読む前にこの境界を UI として確認するための小さな足場です。

MediaPipe Tasks are the fastest path through ready-made APIs, but checking the WASM fileset path, SIMD availability, delegate, and UI-thread pressure early reduces surprises. LiteRT.js can handle custom `.tflite` models and WebGPU / WebNN, but model conversion, pre/post-processing, WASM placement, and fallback for browsers without WebGPU become production responsibilities. Today's sample is a small scaffold for confirming this boundary in the UI before reading a real model.
