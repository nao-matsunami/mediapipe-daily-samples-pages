今日の重要トピック

  1. Gesture Recognizer Web guide は `runningMode` に IMAGE / VIDEO を示し、video や camera frame では `recognizeForVideo()` を使って frame ごとに処理する構成を説明している。

    The Gesture Recognizer Web guide lists IMAGE and VIDEO `runningMode` values and describes using `recognizeForVideo()` frame by frame for video or camera streams.

  2. 同 guide は `recognize()` / `recognizeForVideo()` が同期的に実行され UI thread を block し得るため、camera input では worker や cadence 制御を検討する必要があると明記している。

    The same guide states that `recognize()` and `recognizeForVideo()` run synchronously and may block the UI thread, so camera input should consider workers or cadence control.

  3. Gesture Recognizer の結果は handedness、gestures、21 hand landmarks、21 world landmarks を含むため、gesture label だけでなく座標・奥行き・左右手も command router に渡せる。

    Gesture Recognizer results include handedness, gestures, 21 hand landmarks, and 21 world landmarks, so command routers can use coordinates, depth, and left/right hand context in addition to labels.

  4. canned gesture classifier options には score threshold、max results、allowlist、denylist があり、allowlist と denylist は同時利用しない policy として設計するのがよい。

    Canned gesture classifier options include score threshold, max results, allowlist, and denylist; allowlist and denylist should be modeled as mutually exclusive policies.

  5. npm の @mediapipe/tasks-vision は latest が 1.0.1 と確認でき、nightly / rc tag も継続しているため、サンプル側では import version と wasm path を固定して観察できるようにしておきたい。

    npm shows @mediapipe/tasks-vision latest at 1.0.1 with continuing nightly / rc tags, so samples should pin import versions and wasm paths when observing runtime behavior.

注目事例と何が面白いか

Notable example and why it matters

今日の注目は、Gesture Recognizer を gesture label の demo としてではなく、camera stream から UI command へ渡る runtime pipeline として見ることです。公式 guide は `recognizeForVideo()` の frame 処理、同期 block、worker 実装の検討、handedness / gestures / landmarks / world landmarks を説明しています。面白いのは、モデル精度を上げなくても、timestamp 重複除外、queue cap、古い結果の破棄、dwell gate だけで体感の安定性が大きく変わる点です。

Today's notable angle is treating Gesture Recognizer not as a gesture-label demo but as a runtime pipeline from camera stream to UI command. The official guide describes frame processing through `recognizeForVideo()`, synchronous blocking, worker considerations, and handedness / gestures / landmarks / world landmarks. The interesting part is that duplicate timestamp skipping, queue caps, stale result rejection, and dwell gates can greatly improve perceived stability without changing model accuracy.

制作に使えそうな技術メモ

Production note

実装する時は、`FilesetResolver.forVisionTasks()` と `GestureRecognizer.createFromOptions()` を setup phase に分け、`runningMode: "VIDEO"`、`numHands`、`minHandDetectionConfidence`、`minHandPresenceConfidence`、`minTrackingConfidence`、canned classifier options を設定ログに残します。video loop では `video.currentTime` または monotonic timestamp を比較して同じ frame を捨て、worker から戻る結果は timestamp が最新かを確認してから UI に反映します。gesture label は score threshold だけでなく、dwell と cooldown を通して command 化すると誤発火が減ります。

For implementation, split `FilesetResolver.forVisionTasks()` and `GestureRecognizer.createFromOptions()` into setup phase logging, including `runningMode: "VIDEO"`, `numHands`, `minHandDetectionConfidence`, `minHandPresenceConfidence`, `minTrackingConfidence`, and canned classifier options. In the video loop, compare `video.currentTime` or another monotonic timestamp to drop repeated frames, and only apply worker results to the UI after checking that their timestamps are current. Gesture labels should pass through dwell and cooldown in addition to score threshold before becoming commands.
