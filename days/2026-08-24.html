今日の重要トピック

  1. Face Landmarker Web guide は、顔ランドマークだけでなく blendshape scores と facial transformation matrices を出力できることを明記しており、表情UIや顔エフェクトの入力として使いやすい。

    The Face Landmarker Web guide states that the task can output blendshape scores and facial transformation matrices in addition to face landmarks, making it useful as input for expression UIs and face effects.

  2. `outputFaceBlendshapes` と `outputFacialTransformationMatrixes` は既定では false なので、表情係数や変換行列を使うサンプルでは明示的に有効化する必要がある。

    `outputFaceBlendshapes` and `outputFacialTransformationMatrixes` default to false, so samples that use expression coefficients or transformation matrices must enable them explicitly.

  3. Web guide は `detect()` / `detectForVideo()` が同期実行で UI thread をブロックする点も示しているため、カメラ常時処理では Worker 化や frame skip の検討が早めに必要になる。

    The Web guide also notes that `detect()` and `detectForVideo()` run synchronously and block the UI thread, so camera loops need early Worker or frame-skip planning.

  4. 公式 mediapipe-samples-web の Face Landmarker 実装は confidence sliders、worker、blendshape / matrix 出力ONの構成を持ち、最小試作の実装境界を考える参考になる。

    The official mediapipe-samples-web Face Landmarker implementation uses confidence sliders, a worker, and enabled blendshape / matrix output, which helps define a practical minimal prototype boundary.

  5. 今日の自作サンプルでは、外部デモを並べるのではなく、blendshape を smooth / gate / cue log に変換するアプリ側の薄い層を中心にした。

    Today's original samples center on the application-side layer that smooths, gates, and logs blendshape cues instead of listing external demos.

注目事例と何が面白いか

Notable example and why it matters

Today's notable point is not mesh drawing but the way blendshape scores and facial transformation matrices become interaction vocabulary for an app. The official Web guide explains that Face Landmarker can return 3D face landmarks, expression blendshape scores, and transformation matrices for face effects. The original sample groups them into small semantic signals such as smile, brow, jaw, and head drift, then converts them into UI cues through thresholds and smoothing.

表現・インタラクションのアイデア

Expression and interaction idea

本命サンプルは、アップロード画像、Webカメラ、合成フィードの3入力を持ち、Face Landmarker が使える環境では実モデルから blendshape を読みます。表情スコアは caption brighten、zoom emphasis、hold-to-record のようなUI動作へ変換され、顔が検出できない場合も合成フィードで変換層だけを確認できます。派生サンプルは、モデル出力を待たずに threshold、hold ms、release gap、cooldown ms を動かし、誤発火を減らすヒステリシス設計を即時に試せます。

The main sample supports uploaded images, webcam, and synthetic input, reading blendshapes from the real Face Landmarker model when available. Expression scores become UI actions such as caption brighten, zoom emphasis, and hold-to-record, while the synthetic feed still tests the conversion layer when no face is detected. The derivative sample tunes threshold, hold time, release gap, and cooldown without waiting for model output, quickly testing hysteresis choices that reduce false triggers.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

蓄積できるデータは、入力種別、検出 latency、face count、smile / brow / jaw / head scores、smoothing、threshold、hold time、release gap、cooldown、cue log です。IndexedDB に保存すれば、端末や照明条件ごとの表情トリガー調整ログになります。Web Audio と組み合わせると jawOpen で録音cue、brow raise でズーム音、smile で字幕色変更ができます。Face Detector と組み合わせれば顔矩形の安定性を、WebXR と組み合わせれば表情で空間UIを選ぶ流れを試せます。

The samples can accumulate input type, detection latency, face count, smile / brow / jaw / head scores, smoothing, threshold, hold time, release gap, cooldown, and cue logs. Saved to IndexedDB, those become calibration logs by device and lighting condition. With Web Audio, jawOpen can trigger recording cues, brow raise can trigger zoom sounds, and smile can change caption color. Combined with Face Detector it can compare face-box stability; combined with WebXR it can test expression-driven spatial UI selection.

制作に使えそうな技術メモ

Production note

静的HTMLでは `@mediapipe/tasks-vision@0.10.22/+esm` を dynamic import し、WASM path も同じ version に固定しました。モデルは公式 storage の `face_landmarker.task` を参照し、`FaceLandmarker.createFromOptions()` で `runningMode`、confidence、`outputFaceBlendshapes: true`、`outputFacialTransformationMatrixes: true` を指定しています。`detectForVideo()` は同期実行なので、実運用では Worker と OffscreenCanvas に移し、UIは最後に届いた結果だけを描く構成が必要です。

The static HTML dynamically imports `@mediapipe/tasks-vision@0.10.22/+esm` and pins the matching WASM path. It references the official storage `face_landmarker.task` model and calls `FaceLandmarker.createFromOptions()` with running mode, confidence values, `outputFaceBlendshapes: true`, and `outputFacialTransformationMatrixes: true`. Because `detectForVideo()` is synchronous, production use should move detection into a Worker with OffscreenCanvas and render only the latest result on the UI thread.

The selected main prototype is `Face Blendshape Trigger Mixer`. The working pieces are Tasks Vision dynamic import, `FilesetResolver.forVisionTasks()`, loading the official Face Landmarker task bundle, image / camera / synthetic feeds, smoothing blendshape-like scores, smile / brow / jaw triggers, and a cue log. Next additions should include Worker-side `detectForVideo()`, effect anchors from transformation matrices, Web Audio cues, cue JSON export, and IndexedDB calibration history. The derivative prototype is `Expression Cue Hysteresis Board`, which quickly tests threshold, hold, release gap, and cooldown using synthetic blendshape streams.
