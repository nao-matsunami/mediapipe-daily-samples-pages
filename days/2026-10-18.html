注目事例と何が面白いか

Notable example and why it matters

MediaPipe v1.1.1 は Interactive Segmenter の LiteRT delegate を Android で有効にし、JavaScript の Retrieval SDK コード例も更新しました。これは推論精度だけでなく、どの処理を今フレームで終え、どの検索根拠を限られた文脈へ入れるかをプロダクトが選ぶ段階に来ていることを示します。公式デモを一覧として転載せず、その周辺の判断を自作 UI にしました。

MediaPipe v1.1.1 enables a LiteRT delegate for Interactive Segmenter on Android and refreshes Retrieval SDK JavaScript snippets. This highlights a product-level decision: which work finishes this frame and which evidence fits limited context. Rather than republishing official demos, this builds original UI around those decisions.

表現・インタラクションのアイデア

Expression and interaction idea

本命は `Interactive Mask Frame Budget`。キャンバス上で ROI を作ると、品質・GPU 速度・frame budget から推定コストを算出し、採用したマスクと保留されたマスクを色と点線で分けます。派生 `Retrieval Snippet Fit Lab` は top-K、圧縮率、context budget を動かし、何件が採用され関連度をどこまで残せるかを即時表示します。

The main `Interactive Mask Frame Budget` creates ROIs on a canvas, estimates their cost from quality, GPU speed, and frame budget, and separates accepted and deferred masks by color and dashed lines. The derivative `Retrieval Snippet Fit Lab` adjusts top-K, compression, and context budget to show retained items and relevance immediately.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

残すと価値があるデータは ROI 座標、mask confidence、入力 timestamp、delegate、推論時間、採用・保留理由、検索 query、score、citation、圧縮後 token 数です。InteractiveSegmenter、ObjectDetector、SemanticRetriever、Performance API、IndexedDB、Web Audio を組み合わせれば、操作の速さに合わせてマスク品質を変える編集面や、根拠を捨てずにローカル検索を要約する読書面へ発展します。

Useful records include ROI coordinates, mask confidence, input timestamps, delegate, inference time, accept/defer reason, query, score, citation, and compressed token count. Combining InteractiveSegmenter, ObjectDetector, SemanticRetriever, Performance API, IndexedDB, and Web Audio can grow this into adaptive editing or local evidence-preserving reading surfaces.

制作に使えそうな技術メモ

Production note

リアルタイム系では先に『許容する表示遅延』を決め、ROI ごとの推論時間を移動平均で見積もって budget を超える仕事を next frame に送ります。delegate 切替は初期化時間と精度も別計測にします。retrieval は score の尺度を混ぜず、モデル出力・rerank・圧縮後の citation を別々に残します。ユーザーの画像・query・metrics を保存または送信する前には目的、同意、削除方法を UI で示します。

For real-time work, decide allowable display delay first, estimate per-ROI work with a moving average, and defer excess work to the next frame. Measure delegate initialization and quality separately. For retrieval, retain model score, rerank score, and compressed citation separately. Show purpose, consent, and deletion controls before storing or sending images, queries, or metrics.

試すならこれ

If you try one thing

本命で quality を 0.8 以上、frame budget を 12ms 以下にして複数の ROI をドラッグしてください。採用と保留の境目が見えます。派生では context budget を 300 tokens 前後、圧縮率を 60% 前後にして、top-K を増やした時にどの候補が予算外になるかを比べます。

In the main sample, set quality above 0.8 and frame budget below 12ms, then drag multiple ROIs to expose the accept/defer boundary. In the derivative, set context budget near 300 tokens and compression near 60%, then increase top-K to compare what falls outside budget.
