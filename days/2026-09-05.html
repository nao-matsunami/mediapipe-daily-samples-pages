注目事例と何が面白いか

Notable example and why it matters

今日の注目は Image Classifier の ROI とフィルタです。公式 task overview は ROI classification、score threshold、top-k、allowlist/denylist を主要機能として挙げており、Web guide は `classify()` / `classifyForVideo()` の同期実行が UI thread を塞ぎ得る点も示しています。単に画像にラベルを付けるだけでなく、どこを見て、どのスコアを採用し、何フレーム連続したら UI 状態を変えるかを先に触れるようにすると、実モデル接続後の調整がかなり楽になります。

Today's notable example is Image Classifier ROI and filtering. The official task overview highlights ROI classification, score threshold, top-k, and allowlist/denylist, while the Web guide notes that `classify()` / `classifyForVideo()` can block the UI thread. The interesting part is not just labeling an image, but making the watched region, accepted score, and consecutive-frame rule tunable before real model integration.

表現・インタラクションのアイデア

Expression and interaction idea

本命サンプル `Image Classifier ROI Stability Lab` は、机上の物体を模した canvas scene に黄色の ROI を置き、ドラッグで見ている領域を変えると top classification が変化します。threshold、ROI size、maxResults、confirm frames を動かすと、結果が「表示される」「保留される」「安定カテゴリとして採用される」流れが timeline で見えます。派生の `Classifier Filter Policy Lab` は、同じ分類結果をアプリのポリシーに通す前段として、allowlist、denylist、scoreThreshold、maxResults の結果を即時に確認します。

The main sample, `Image Classifier ROI Stability Lab`, places a yellow ROI over a synthetic desktop canvas scene; dragging the ROI changes the top classification. Moving threshold, ROI size, maxResults, and confirm frames shows when a result is visible, held, or accepted as stable. The derivative `Classifier Filter Policy Lab` checks allowlist, denylist, scoreThreshold, and maxResults as an app policy stage before real classification output is wired in.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

蓄積できるデータは、ROI 中心、ROI サイズ、top category、score、visible result count、threshold、maxResults、streak、stable label、accept/reject timeline、policy mode、allow/deny 対象です。これを実 Image Classifier の `ImageClassifierResult`、Object Detector の bbox、Image Segmenter の mask、Image Embedder の類似度、Hand Landmarker の指差し座標、Web Worker の latency 計測、IndexedDB の分類履歴と組み合わせると、指で指した物だけを分類する UI、棚卸しレビュー、カメラ内の関心領域だけを低頻度分類する省負荷設計、誤カテゴリを隠す公開ダッシュボードに発展できます。

The samples can collect ROI center, ROI size, top category, score, visible result count, threshold, maxResults, streak, stable label, accept/reject timeline, policy mode, and allow/deny targets. Combined with real `ImageClassifierResult`, Object Detector boxes, Image Segmenter masks, Image Embedder similarity, Hand Landmarker pointing coordinates, Web Worker latency metrics, and IndexedDB history, they can become point-to-classify UI, inventory review, low-cost region-only camera classification, or dashboards that hide unwanted categories.

制作に使えそうな技術メモ

Production note

静的 HTML では疑似分類で挙動を固定しつつ、`@mediapipe/tasks-vision@1.0.1/+esm` の dynamic import preflight を本命サンプルに置きました。本番化する時は `FilesetResolver.forVisionTasks()`、`ImageClassifier.createFromOptions()`、EfficientNet-Lite0 などの modelAssetPath、`scoreThreshold`、`maxResults` を実設定に移し、video 入力では `classifyForVideo(video, performance.now())` を worker 側へ逃がします。ROI を実 Task に渡す場合は `ImageProcessingOptions` の座標系、canvas 表示座標、video の実ピクセル座標を混同しないように、変換関数を1か所に閉じ込めるのが安全です。

The static HTML keeps behavior deterministic with synthetic classifications, while the main sample includes a dynamic import preflight for `@mediapipe/tasks-vision@1.0.1/+esm`. For production, move the settings into `FilesetResolver.forVisionTasks()`, `ImageClassifier.createFromOptions()`, an EfficientNet-Lite0 modelAssetPath, `scoreThreshold`, and `maxResults`; for video input, move `classifyForVideo(video, performance.now())` into a worker. If ROI is passed to a real Task, keep `ImageProcessingOptions`, canvas display coordinates, and video pixel coordinates separated behind one conversion function.

試すならこれ

If you try one thing

Open `Image Classifier ROI Stability Lab` and drag the yellow ROI over the lamp, plant, mug, and notebook. Raising `Score threshold` increases rejects, while increasing `Confirm frames` delays stable-label acceptance. In the derivative sample, selecting `both lists` produces a configuration error so the allowlist/denylist conflict is caught before implementation.
