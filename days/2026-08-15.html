注目事例と何が面白いか

Notable example and why it matters

今日の注目は、MediaPipe LLM Inference の Web ガイドに maintenance-only と LiteRT-LM.js への移行推奨が明記されている点です。大きな `.litertlm` モデルをいきなり配布する前に、ブラウザが WebGPU を使えるか、プロンプトと履歴が context に収まるかを測る道具が必要になります。自作サンプルでは推論そのものではなく、移行前の判断面を最小 UI にしました。

Today's notable point is that the MediaPipe LLM Inference Web guide explicitly marks that API as maintenance-only and recommends moving Web projects to LiteRT-LM.js. Before distributing a large `.litertlm` model, developers need a way to check whether the browser can use WebGPU and whether the prompt plus history fits the context. The original sample focuses on that pre-migration decision surface rather than inference itself.

Switching presets and moving history turns, max output tokens, temperature, top K, and safety reserve updates prompt tokens, estimated total, memory hint, and readiness score immediately. `Check LiteRT-LM.js` only tests the CDN module import without downloading a model, keeping the public page lightweight.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

蓄積できるデータは prompt text、preset、rough token count、history turns、max output tokens、temperature、top K、reserve、WebGPU adapter、LiteRT-LM.js import result、readiness score、compact 操作です。Text Classifier で危険な入力を gate し、Text Embedder で既存ナレッジとの近さを見て、IndexedDB にセッション予算を保存すると、ローカル LLM の導入前診断ツールになります。将来は実モデル選択、Storage quota、Battery Status、Web Worker 分離、RAG chunk 設計にも広げられます。

The sample can accumulate prompt text, preset, rough token count, history turns, max output tokens, temperature, top K, reserve, WebGPU adapter, LiteRT-LM.js import result, readiness score, and compact actions. Combined with Text Classifier for unsafe-input gates, Text Embedder for knowledge proximity, and IndexedDB for session budgets, it becomes a preflight tool for local LLM adoption. It can later expand to real model selection, storage quota, battery state, Web Worker isolation, and RAG chunk design.

制作に使えそうな技術メモ

Production note

LiteRT-LM API Overview は JavaScript で `@litert-lm/core` から `Engine.create({ model })`、`createConversation()`、`sendMessage()` へ進む流れを示しています。Web SDK は WebGPU acceleration が既定で、現時点では text-in / text-out と説明されています。サンプルでは `navigator.gpu.requestAdapter()` で WebGPU を確認し、`import('https://cdn.jsdelivr.net/npm/@litert-lm/core/+esm')` で `Engine` export の有無だけを検証します。実モデルの取得はユーザー同意、容量、ライセンス確認が必要なので今日は行いません。

The LiteRT-LM API Overview shows the JavaScript path from `Engine.create({ model })` through `createConversation()` to `sendMessage()` using `@litert-lm/core`. It says the Web SDK uses WebGPU acceleration by default and currently supports text-in / text-out. The sample checks WebGPU via `navigator.gpu.requestAdapter()` and verifies only the `Engine` export with `import('https://cdn.jsdelivr.net/npm/@litert-lm/core/+esm')`. Downloading an actual model needs user consent, capacity checks, and license review, so it is intentionally out of scope today.

俯瞰メモ

Bird's-eye memo

Previous samples converted Vision, Text, and Audio Task outputs into UI decisions. Today broadens the scope to Google AI Edge on-device GenAI and handles environment, capacity, and context length before inference rather than inference outputs. In Web ML, small diagnostic UIs that show whether a model can run are as important as the model invocation code.
