注目事例と何が面白いか

Notable example and why it matters

公式 Image Segmenter API はライブ入力の timestamp を単調増加にし、低遅延化のため一部入力が処理されない場合があると説明します。これは失敗ではなく、最新性を選ぶ設計です。本命試作では捨てた入力、処理中、古くなった結果、実際に描いた結果を別々の花にして、この選択を画面へ出しました。

The official live API permits drops for latency. The main probe turns each outcome into a distinct flower.

表現・インタラクションのアイデア

Expression and interaction idea

本命は cadence、推論レーン、鮮度上限を動かすと庭が混む仕掛けです。派生は年齢を色・上下位置・短い音へ写します。利用者は精度数値だけでなく、『いま表示している結果が何ms前か』を直感的に読めます。

Map result age to color, position, and a short sound rather than hiding it behind one accuracy number.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

映像そのものを保存せず、入力時刻、callback時刻、drop理由、選んだbackend、表示可否だけを同意付きで蓄積できます。Performance API、MediaPipe Tasks callback、Web Audio、IndexedDB、後日の SemanticRetriever を組み合わせれば、端末ごとの『遅いが安定』『速いが古い』を検索可能な品質地図にできます。

Consent-based timing metadata can become a searchable quality map without retaining camera imagery.

制作に使えそうな技術メモ

Production note

VIDEO/LIVE_STREAM では timestamp を入力採番時に確定し、callback時に現在時刻との差を測ります。キューを無制限にせず、busyなら drop、古い結果なら hold と決めます。UIは drop を例外として隠さず、件数・年齢・現在のfallbackを開示します。

Timestamp at capture, bound the queue, and expose drop/hold decisions in the UI.

試すならこれ

If you try one thing

本命で cadence を45fps、推論を420ms、鮮度を40msにします。赤と紫が増え、表示数だけでは品質を判断できないことが分かります。次に派生で音を有効化し、古い結果の低い音を確認してください。

Max cadence and latency while minimizing freshness, then listen for held-result tones.

俯瞰メモ

Bird's-eye memo

オンデバイスMLのUXは『推論できた』かだけでは足りません。どの瞬間の入力を、どの負荷のもとで、いつ表示したのかが利用者の行動を左右します。落ちることを前提にした可視化は、低遅延を損なわず信頼を上げる設計になります。

On-device ML UX needs time and load context, not just an inference-success bit.
