注目事例と何が面白いか

Notable example and why it matters

今日の注目は、Hand Landmarker や Gesture Recognizer の推論結果をそのまま UI 操作へ流すのではなく、ランドマークの揺れ、presence 低下、tracking confidence、gesture score の曖昧さを一段整えてから使うことです。公式 guide は Task の作り方と結果形状を示しますが、日次アーカイブ側ではその後段にある「操作として信じてよいか」を自作サンプルで可視化しました。

Today's notable point is not to pass Hand Landmarker or Gesture Recognizer outputs directly into UI actions. Instead, smooth landmark jitter and gate presence loss, tracking confidence, and ambiguous gesture scores first. The official guides show task setup and result shapes; this archive visualizes the downstream question of whether the output is reliable enough to become an action.

表現・インタラクションのアイデア

Expression and interaction idea

本命の `Landmark Jitter Smoothing Lab` は、21点の手ランドマークを raw amber / smoothed green で重ね、jitter、motion speed、smoothing、tracking threshold によって smooth / reuse / detect / reacquire が切り替わります。派生の `Gesture Intent Hysteresis Probe` は、Open_Palm、Pointing_Up、Victory、Closed_Fist の score を合成し、enter / exit threshold、dwell frames、cooldown で fire / hold / cooldown / drop を振り分けます。

The main sample, `Landmark Jitter Smoothing Lab`, overlays 21 synthetic hand landmarks as raw amber and smoothed green, then switches between smooth / reuse / detect / reacquire based on jitter, motion speed, smoothing, and tracking threshold. The derivative, `Gesture Intent Hysteresis Probe`, synthesizes scores for Open_Palm, Pointing_Up, Victory, and Closed_Fist, then routes them through enter / exit thresholds, dwell frames, and cooldown.

The samples can accumulate raw normalized landmarks, smoothed landmarks, jitter RMS, presence, tracking, reacquire counts, gesture scores, score gaps, dwell counts, and fire / hold / drop history. Combined with real Hand Landmarker / Gesture Recognizer tasks, DrawingUtils, PerformanceObserver, workers, IndexedDB, Web Audio, XR pointers, or an LLM command router, false triggers from vision input to action can be analyzed later.

制作に使えそうな技術メモ

Production note

実装では `detectForVideo()` の timestamp 重複を避け、同期実行で UI スレッドを塞ぐ時間を測り、confidence が落ちた時は前回結果の reuse と palm detector / recognizer 再実行を分けます。ランドマーク描画は DrawingUtils の connectors / landmarks に寄せつつ、アプリ側の smoothing と hysteresis は別レイヤーに置くと調整しやすいです。

In production, avoid duplicate timestamps for `detectForVideo()`, measure synchronous UI-thread blocking, and separate previous-result reuse from palm detector / recognizer reacquisition when confidence drops. Landmark rendering can follow DrawingUtils connectors / landmarks, while application-level smoothing and hysteresis stay in a separate adjustable layer.
