注目事例と何が面白いか

Notable example and why it matters

今日の注目は Object Detector の検出結果そのものではなく、検出を始める前の asset / delegate preflight です。公式 Web guide は `FilesetResolver.forVisionTasks()` と `ObjectDetector.createFromOptions()` で WASM とモデルを準備し、`modelAssetPath`、`scoreThreshold`、`runningMode` を渡す流れを示しています。Web setup guide では BaseOptions の `modelAssetPath` と CPU/GPU delegate が整理されているため、初回起動の体感遅延、モデル URL の失敗、GPU fallback を UI として点検しやすい形にしました。

Today's notable angle is not the Object Detector result itself, but the asset / delegate preflight before detection starts. The official Web guide prepares WASM and the model with `FilesetResolver.forVisionTasks()` and `ObjectDetector.createFromOptions()`, passing `modelAssetPath`, `scoreThreshold`, and `runningMode`. The Web setup guide documents BaseOptions `modelAssetPath` and CPU/GPU delegate configuration, so this turns first-start latency, model URL failures, and GPU fallback into an inspectable UI.

制作に使えそうな技術メモ

Production note

実接続時は Web setup guide に合わせて `@mediapipe/tasks-vision` の version と WASM path を固定し、`FilesetResolver.forVisionTasks(basePath)`、`ObjectDetector.createFromOptions(vision, { baseOptions: { modelAssetPath, delegate }, scoreThreshold, runningMode })`、`detect()` / `detectForVideo()` を分けて計測します。モデル URL は 404 / CORS / cache miss を区別し、GPU first の場合は初期化失敗時に CPU route を明示的にログへ残すと、ユーザー環境差の調査が楽になります。

When connecting a real model, pin the `@mediapipe/tasks-vision` version and WASM path according to the Web setup guide, then measure `FilesetResolver.forVisionTasks(basePath)`, `ObjectDetector.createFromOptions(vision, { baseOptions: { modelAssetPath, delegate }, scoreThreshold, runningMode })`, and `detect()` / `detectForVideo()` separately. For model URLs, distinguish 404, CORS, and cache misses; when using GPU-first, log explicit CPU fallback after startup failure so device-specific issues are easier to debug.
