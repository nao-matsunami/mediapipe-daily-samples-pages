今日の重要トピック

  1. Tasks Vision の JavaScript API reference は `FilesetResolver`、`FaceDetector`、`GestureRecognizer`、`HandLandmarker`、`ImageSegmenter`、`ObjectDetector`、`PoseLandmarker` などの Web task class を整理している。

    The Tasks Vision JavaScript API reference organizes Web task classes such as `FilesetResolver`, `FaceDetector`, `GestureRecognizer`, `HandLandmarker`, `ImageSegmenter`, `ObjectDetector`, and `PoseLandmarker`.

  2. `FilesetResolver` は SIMD 対応を確認して必要な WASM fileset を解決する。WASM ファイルをリネームせずに公開する必要があるため、CDN pin や local copy の検証が重要になる。

    `FilesetResolver` checks SIMD support and resolves the required WASM fileset. Because the WASM files need to be published without renaming, CDN pinning and local-copy verification matter.

  3. MediaPipe Tasks Web Vision README は `FilesetResolver.forVisionTasks()` と model path から task を作る最小形を示しており、実装の最初の失敗点は import、WASM、model URL、delegate の4つに分けられる。

    The MediaPipe Tasks Web Vision README shows the minimal shape of `FilesetResolver.forVisionTasks()` plus task creation from a model path, making import, WASM, model URL, and delegate the first four likely failure points.

  4. 公式 web demo は delegate 設定、model selection、WASM module loading、GPU unavailable 時の CPU fallback 表示を持ち、公開UIでも失敗理由をユーザーに返す設計が必要だと分かる。

    The official web demo includes delegate settings, model selection, WASM module loading, and CPU fallback messaging when GPU is unavailable, showing that published UIs should explain failure causes.

  5. running mode は image、video、live stream 系に分かれ、video/live stream では timestamp と busy frame の扱いが latency 設計に直結する。

    Running modes separate image, video, and live stream styles; timestamp handling and busy-frame policy in video/live stream modes directly affect latency design.

注目事例と何が面白いか

Notable example and why it matters

今日の注目は、公式デモにも見える delegate と asset loading の失敗状態です。MediaPipe Tasks の実コードではモデル精度より前に、ESM import、WASM fileset、model asset、delegate のどこで止まったかを切り分ける必要があります。面白いのは、これは ML そのものではなく Web アプリの起動設計の問題で、先に小さな router と sentinel を作るだけでユーザー体験がかなり安定する点です。

Today's notable point is the delegate and asset-loading failure state visible in the official demo. In real MediaPipe Tasks code, before model accuracy matters, the app needs to distinguish whether ESM import, WASM fileset, model asset, or delegate selection failed. The interesting part is that this is mostly a Web app startup-design problem, and a small router plus sentinel can make the user experience much steadier.

表現・インタラクションのアイデア

Expression and interaction idea

本命サンプル `Delegate Fallback Latency Router` は、preferred delegate、running mode、frame budget、GPU availability、GPU init tax、main-thread spike を動かし、CPU / GPU / AUTO の採用理由をタイムラインで表示します。派生の `WASM Asset Path Sentinel` は、FilesetResolver に渡す base path から vision/audio/genai の候補 asset を軽く probe し、404、CORS、offline、renamed asset をカメラ許可前に説明する小さな UI です。

The main sample, `Delegate Fallback Latency Router`, lets you adjust preferred delegate, running mode, frame budget, GPU availability, GPU initialization tax, and main-thread spikes, then shows why CPU, GPU, or AUTO was selected on a timeline. The derivative `WASM Asset Path Sentinel` lightly probes candidate vision/audio/genai assets from a FilesetResolver base path and explains 404, CORS, offline, or renamed-asset states before asking for camera permission.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

蓄積できるデータは、preferred delegate、実際に採用した delegate、running mode、frame budget、推定処理時間、budget 超過、asset URL、HTTP status、fallback 理由です。実 Face / Hand / Pose / Object / Audio tasks、PerformanceObserver、WebGL/WebGPU capability、Service Worker cache、IndexedDB 起動ログ、ユーザー向け consent 表示と組み合わせると、環境ごとに最初から軽い設定へ誘導するオンデバイス ML 起動パネルにできます。

The samples can accumulate preferred delegate, selected delegate, running mode, frame budget, estimated processing time, budget misses, asset URL, HTTP status, and fallback reason. Combined with real Face, Hand, Pose, Object, or Audio tasks, PerformanceObserver, WebGL/WebGPU capability checks, Service Worker cache, IndexedDB startup logs, and user-facing consent messaging, this can become an on-device ML startup panel that routes each environment to a lighter setting from the beginning.

制作に使えそうな技術メモ

Production note

本命 HTML は `@mediapipe/tasks-vision@1.0.1/+esm` を dynamic import し、`FilesetResolver`、`FaceDetector`、`HandLandmarker` の export と WebGL availability を確認します。実装へ進める時は、`FilesetResolver.forVisionTasks(basePath)`、task の `createFromOptions`、`baseOptions.delegate`、`runningMode: "VIDEO"` または `"LIVE_STREAM"`、timestamp、busy frame policy を分けてログ化します。派生 HTML は HEAD/GET で asset 候補を点検し、公開先で WASM 名が変わっていないかを先に可視化します。

The main HTML dynamically imports `@mediapipe/tasks-vision@1.0.1/+esm` and checks `FilesetResolver`, `FaceDetector`, `HandLandmarker`, and WebGL availability. When wiring a real task, log `FilesetResolver.forVisionTasks(basePath)`, task `createFromOptions`, `baseOptions.delegate`, `runningMode: "VIDEO"` or `"LIVE_STREAM"`, timestamps, and busy-frame policy separately. The derivative HTML probes candidate assets with HEAD/GET so a published app can see whether WASM names changed before initialization.
