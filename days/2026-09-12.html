今日の重要トピック

  1. Object Detector は still image、decoded video frame、live video feed を入力にし、category、score、bounding box を返すため、UI 側では一時的な欠落や低 score をどう扱うかが重要になる。

    Object Detector accepts still images, decoded video frames, and live video feeds, returning category, score, and bounding boxes, so UI code needs a policy for temporary misses and low scores.

  2. Object Detector の option には score threshold、max results、display name locale、category allowlist / denylist があり、検出結果の見せ方やイベント化の境界を作りやすい。

    Object Detector options include score threshold, max results, display name locale, and category allowlist / denylist, which are useful boundaries for visual display and event conversion.

  3. MediaPipe Tasks Web は vision/text/audio などの package と FilesetResolver の base path に依存するため、実モデルの前に import、WASM、delegate、asset path の preflight を分けて考える必要がある。

    MediaPipe Tasks Web depends on vision/text/audio packages plus a FilesetResolver base path, so import, WASM, delegate, and asset-path preflight should be separated before loading real models.

  4. 公式 mediapipe-samples-web はブラウザだけで Vision / Audio / Text tasks を試す構成を持ち、自作サンプルではそこから UI 設計の要点だけを抜き出すのがよい。

    The official mediapipe-samples-web project provides browser-only demos for Vision, Audio, and Text tasks; today's original samples pull out the UI design lessons rather than listing external demos.

  5. Web ML のライブ UI では、毎フレーム推論よりも detector cadence、busy frame skip、ROI decay、confirmation frames を明示した方が、端末差に強い体験を作りやすい。

    For live Web ML UI, detector cadence, busy-frame skipping, ROI decay, and confirmation frames often produce a more device-tolerant experience than trying to infer on every frame.

注目事例と何が面白いか

Notable example and why it matters

今日の注目は Object Detector の option 群です。公式 guide では score threshold、max results、display name locale、allowlist / denylist が整理されており、これは推論精度の調整だけでなく「ユーザーに見せる box」「まだ見せない label」「イベント化してよい category」を切るための UI ポリシーとして使えます。面白いのは、検出モデルを変えなくても、ROI の寿命や confirmation frames だけでライブ画面のちらつきと誤発火をかなり減らせる点です。

Today's notable point is the Object Detector option set. The official guide highlights score threshold, max results, display name locale, and allowlist / denylist; these are not only model-output filters but also UI policy controls for visible boxes, hidden labels, and event-safe categories. The interesting part is that even without changing the model, ROI lifetime and confirmation frames can reduce flicker and false event firing in live views.

表現・インタラクションのアイデア

Expression and interaction idea

本命サンプル `Object Detector ROI Decay Board` は、合成 detection を score threshold と max results に通し、毎フレーム検出しない場合でも ROI cache を half-life で薄く残します。派生の `Detector Label Policy Sandbox` は allowlist / denylist、score threshold、confirmation frames、locale 表示を操作し、検出カテゴリを accepted / pending / suppressed に分けます。どちらも外部デモの埋め込みではなく、この workspace 内で動く最小 UI として作りました。

The main sample, `Object Detector ROI Decay Board`, sends synthetic detections through score threshold and max results, then keeps an ROI cache fading by half-life even when detection does not run every frame. The derivative, `Detector Label Policy Sandbox`, lets you adjust allowlist / denylist, score threshold, confirmation frames, and locale display, classifying categories as accepted, pending, or suppressed. Both are original minimal UIs in this workspace rather than embedded external demos.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

蓄積できるデータは、category、score、bounding box、ROI age、last seen frame、detector cadence、dropout、accepted / pending / suppressed の decision log です。実 Object Detector、Image Embedder、Gesture Recognizer、Pose Landmarker、WebGL overlay、IndexedDB session log、Service Worker cache、LLM による scene note と組み合わせると、ライブカメラ上の物体を安定した UI 状態へ変換する小さな運用パネルにできます。

The samples can accumulate category, score, bounding box, ROI age, last-seen frame, detector cadence, dropout, and accepted / pending / suppressed decision logs. Combined with a real Object Detector, Image Embedder, Gesture Recognizer, Pose Landmarker, WebGL overlays, IndexedDB session logs, Service Worker cache, or LLM scene notes, this can become a small operations panel that turns camera objects into stable UI state.

制作に使えそうな技術メモ

Production note

実装へ進める時は、`FilesetResolver.forVisionTasks(basePath)`、`ObjectDetector.createFromOptions()`、`baseOptions.modelAssetPath`、`runningMode: "VIDEO"` または live stream callback、`scoreThreshold`、`maxResults`、`displayNamesLocale`、`categoryAllowlist` / `categoryDenylist` を分けてログ化します。Web guide で触れられる同期処理の UI blocking リスクを避けるには、カメラフレームを毎回処理せず、cadence と busy flag を置いて `detectForVideo()` の呼び出し頻度を制御するのが扱いやすいです。

For a real implementation, log `FilesetResolver.forVisionTasks(basePath)`, `ObjectDetector.createFromOptions()`, `baseOptions.modelAssetPath`, `runningMode: "VIDEO"` or live-stream callback, `scoreThreshold`, `maxResults`, `displayNamesLocale`, and `categoryAllowlist` / `categoryDenylist` separately. To avoid the UI-blocking risk noted in Web guides for synchronous calls, avoid processing every camera frame and control `detectForVideo()` frequency with a cadence and busy flag.

Open `Object Detector ROI Decay Board`, set Detector cadence to every 4 frames, and press `Start stream` to see boxes persist briefly even on frames without detection. Then press `Simulate dropout` and check whether the ROI cache reduces flicker. In the derivative sample, switch policy to denylist suppress and confirm that sensitive or hidden labels do not become events.
