表現・インタラクションのアイデア

Expression and interaction idea

本命サンプルは、version、import endpoint、WASM path を切り替えて `Run probe` すると、import成否、named exportの充足、WASM取得、採用ルートを棒グラフとログで表示します。`Try matrix` は複数versionを連続検査し、CIや手元ブラウザでの初期化ヘルスチェックに近い体験にしました。派生サンプルは、その結果をどう採用判断へ変えるかをUI化し、latest confidence、legacy compatibility、WASM confidence、regression tolerance から `Use latest`、`Keep pin`、`Canary first` を選びます。

The main sample lets the user switch version, import endpoint, and WASM path, then displays import status, named-export coverage, WASM fetch status, and the recommended route with bars and logs. `Try matrix` checks multiple versions in sequence, approximating a local browser or CI initialization health check. The derivative sample turns those results into an adoption decision, choosing `Use latest`, `Keep pin`, or `Canary first` from latest confidence, legacy compatibility, WASM confidence, and regression tolerance.

制作に使えそうな技術メモ

Production note

静的HTMLで `await import('https://cdn.jsdelivr.net/npm/@mediapipe/tasks-vision@VERSION/+esm')` を実行し、`FilesetResolver` や主要 Vision Task class の named export を確認する構成にしました。WASM側は `fetch()` の HEAD / GET fallback で path の到達性だけを検査します。実Task作成までは行わないため、カメラ権限やモデルDLの揺れを避けて、packagingの問題だけを短時間で再現できます。実運用に足すなら、検査結果をJSON化し、代表Taskを1本だけ実ロードする smoke test を別段に置くのがよさそうです。

The static HTML runs `await import('https://cdn.jsdelivr.net/npm/@mediapipe/tasks-vision@VERSION/+esm')` and checks named exports such as `FilesetResolver` and key Vision Task classes. The WASM side only checks path reachability using `fetch()` with HEAD / GET fallback. Because it does not create a real Task, it avoids camera permission and model-download variability and isolates packaging failures quickly. For production use, export the probe result as JSON and add a separate smoke test that loads one representative Task.
