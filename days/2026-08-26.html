注目事例と何が面白いか

Notable example and why it matters

今日の注目は、Interactive Segmenter が「画像を毎回投げる一発推論」ではなく、画像をセットしたうえでユーザーのクリックやストロークを何度も試す stateful な選択UIとして扱える点です。公式 task guide は新APIを `setImage` + `segment` の流れとして説明し、Web guide は Magic Touch model と positive point の最小コードを示しています。そこで本命サンプルでは、seed canvas またはアップロード画像に対して positive / negative prompt を重ね、実 task が読み込める場合は Interactive Segmenter に渡し、読み込めない場合でも同じUIを合成 confidence mask で検査できるようにしました。

Today's notable point is that Interactive Segmenter can be treated as a stateful selection UI, not as one-shot inference that receives the image every time. The official task guide describes the new API as a `setImage` + `segment` flow, and the Web guide shows the Magic Touch model plus a minimal positive point example. The main sample therefore layers positive / negative prompts on a seeded canvas or uploaded image, sends them to Interactive Segmenter when the real task loads, and keeps the same UI testable with a synthetic confidence mask when it cannot.

表現・インタラクションのアイデア

Expression and interaction idea

本命サンプルは、クリックやドラッグを prompt stack として残し、brush mode、prompt radius、mask threshold、overlay opacity を動かして、選択がどの程度安定するかを確認できます。MediaPipe task が使える環境では `@mediapipe/tasks-vision@0.10.22` と公式 Magic Touch model を読みます。派生サンプルは、次に足すなら必要になる複数マスクの合成ルールを先に検証する小さな道具です。positive prompt、negative guard、latest prompt の優先度、decay、conflict tolerance を変えると、commit / refine の判断が変わります。

The main sample keeps clicks and drags as a prompt stack, then lets brush mode, prompt radius, mask threshold, and overlay opacity reveal how stable the selection is. In environments where the MediaPipe task is available, it loads `@mediapipe/tasks-vision@0.10.22` and the official Magic Touch model. The derivative sample is a small tool for testing the multi-mask composition rules that would be useful next. Adjusting positive prompt, negative guard, latest prompt priority, decay, and conflict tolerance changes the commit / refine decision.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

蓄積できるデータは、source image、prompt sequence、positive / negative mode、stroke length、threshold、coverage、segment latency、mask size、quality score、conflict ratio、commit decision です。IndexedDB に保存すれば、ユーザーがどの順序で前景と背景を指定すると安定するかを比較できます。Image Segmenter の人物マスクと組み合わせると初期マスクを作り、Interactive Segmenter で境界だけを修正するUIにできます。Object Detector の box を初期プロンプトに変換したり、Web Audio で commit 時だけ短い確認音を鳴らしたり、WebCodecs で選択履歴を動画注釈として残す発展も考えられます。

The samples can accumulate source image, prompt sequence, positive / negative mode, stroke length, threshold, coverage, segment latency, mask size, quality score, conflict ratio, and commit decision. Stored in IndexedDB, they can compare which foreground/background prompting order stabilizes selection. Combined with Image Segmenter, a person mask can become the initial mask and Interactive Segmenter can refine only boundaries. Object Detector boxes could become initial prompts, Web Audio can play a short confirmation only on commit, and WebCodecs can preserve the selection history as video annotations.

制作に使えそうな技術メモ

Production note

静的HTMLでは `@mediapipe/tasks-vision@0.10.22/+esm` を dynamic import し、WASM path も同じ version に固定しました。モデルは Web guide と公式サンプルで示される `interactive_segmenter_v2/magic_touch/int8/1/interactive_segmentation.task` を参照しています。新しいAPIでは `setImage()` で画像を登録し、stroke / point を `RegionOfInterest` として `segment()` に渡す流れを想定します。`setImage()` と `segment()` は同期実行で UI thread を止め得るため、公式 worker 実装のように heavy path を Worker / OffscreenCanvas 側に逃がすのが次の実装課題です。

The static HTML dynamically imports `@mediapipe/tasks-vision@0.10.22/+esm` and pins the matching WASM path. It references the `interactive_segmenter_v2/magic_touch/int8/1/interactive_segmentation.task` model shown in the Web guide and official sample. With the new API, the intended flow is to register the image with `setImage()` and pass strokes or points as a `RegionOfInterest` into `segment()`. Because `setImage()` and `segment()` can synchronously block the UI thread, the next implementation step is moving heavy work into a Worker / OffscreenCanvas path like the official worker implementation.

試すならこれ

If you try one thing

First open `Interactive Segmenter Prompt Lab`, keep it in Synthetic ready mode, place positive prompts on the foreground and negative prompts on the background, and adjust the mask threshold. Then press Load Task and send the same prompt path to the real task when model loading works. In the derivative `Prompt Priority Mask Composer`, switch the preset to `Negative guards edge` and lower conflict tolerance to confirm that ambiguous boundaries return to refine instead of committing.
