注目事例と何が面白いか

Notable example and why it matters

今日の注目は、Image Embedder を「画像検索や似た画像比較」だけではなく、video loop の中で ROI が動き続ける時の runtime 部品として扱うことです。公式 guide は cosine similarity と ROI を明確に示し、さらに `embed()` / `embedForVideo()` の同期実行が UI thread を block し得ると説明しています。つまり制作では、毎フレーム embedding を取るより、ROI drift、類似度しきい値、cache 再利用、worker handoff を一緒に設計する方が重要になります。

Today's notable angle is treating Image Embedder not only as image search or pairwise similarity, but as a runtime component inside a video loop where the ROI keeps moving. The official guide clearly covers cosine similarity and ROI, and also explains that `embed()` / `embedForVideo()` can synchronously block the UI thread. In production, the important design is not embedding every frame, but coordinating ROI drift, similarity thresholds, cache reuse, and worker handoff.

表現・インタラクションのアイデア

Expression and interaction idea

本命サンプル `Image Embedder ROI Drift Dashboard` は、ROI speed、embed interval、sync cost、similarity gate、ROI size を触り、embedding refresh と再利用の境界を可視化します。派生の `Embedding Cache Eviction Playground` は、scene drift、cache slots、TTL、reuse threshold、embed cost を操作し、LRU と similarity-first eviction のどちらが体験に合うかを hit rate と stale slot で比べます。

The main sample, `Image Embedder ROI Drift Dashboard`, lets you adjust ROI speed, embed interval, sync cost, similarity gates, and ROI size to visualize the boundary between embedding refresh and reuse. The derivative, `Embedding Cache Eviction Playground`, adjusts scene drift, cache slots, TTL, reuse threshold, and embed cost to compare LRU and similarity-first eviction through hit rate and stale slots.

制作に使えそうな技術メモ

Production note

実装では `FilesetResolver.forVisionTasks()`、`ImageEmbedder.createFromOptions()`、`modelAssetPath`、`runningMode: "VIDEO"`、`ImageProcessingOptions` の ROI、`embedForVideo()`、`ImageEmbedder.cosineSimilarity()` を分けて計測します。`embedForVideo()` を main thread で直接連打せず、ROI が十分変わった時だけ worker 側で embedding を更新し、cache hit の場合は UI だけ更新する設計にすると、体感遅延を抑えやすいです。

For implementation, measure `FilesetResolver.forVisionTasks()`, `ImageEmbedder.createFromOptions()`, `modelAssetPath`, `runningMode: "VIDEO"`, ROI through `ImageProcessingOptions`, `embedForVideo()`, and `ImageEmbedder.cosineSimilarity()` separately. Rather than calling `embedForVideo()` repeatedly on the main thread, update embeddings in a worker only when the ROI changes enough, and update only the UI when cache hits occur.
