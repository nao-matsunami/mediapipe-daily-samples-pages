注目事例と何が面白いか

Notable example and why it matters

v1.1.0 は Web 側で重複する WASM embedding call を防ぐ変更を挙げています。これは単なる内部最適化ではなく、完了順が逆転する UI や、遅い端末で推論待ちが積み上がる体験を設計対象にするサインです。最新の状態を見せるライブ用途では、全結果を保存するより、新しい入力へ収束する方が正しいことがあります。

v1.1.0 explicitly lists prevention of overlapping WASM embedding calls on the Web. This is not merely an internal optimization: it points to reversed completion order and accumulating inference waits as product concerns. For live views, converging on the newest state can be more correct than preserving every result.

表現・インタラクションのアイデア

Expression and interaction idea

本命 `Latest Frame Backpressure Lab` は FPS、推論時間、latest-only / FIFO を操作し、置換数・完了数・結果年齢を動かします。派生 `Latency Quality Ladder` は遅延のしきい値を Instant / Smooth / Steady / Careful という表示方針に変換します。待たせる理由を隠すのでなく、どの表現を軽くしたかまで見せる設計です。

The main `Latest Frame Backpressure Lab` controls FPS, inference cost, and latest-only / FIFO policy while animating replacements, completions, and result age. The derivative `Latency Quality Ladder` turns latency thresholds into Instant / Smooth / Steady / Careful display policies. Rather than hide waiting, it reveals which expression was made lighter.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

保存価値のあるデータは input timestamp、推論開始・終了、queue depth、置換数、結果年齢、モデル版、delegate、端末 capability、選ばれた品質段階です。これを MediaPipe の Face / Hand / Pose Landmarker、Image Segmenter、UniversalEmbedder、Performance API、Worker、IndexedDB、WebGPU capability、端末内 CSV export と組み合わせると、実行品質を再現・説明・比較できる小さな計測面になります。

Useful records include input timestamps, inference start/end, queue depth, replacements, result age, model version, delegate, device capability, and the selected quality tier. Combined with MediaPipe Face/Hand/Pose Landmarkers, Image Segmenter, UniversalEmbedder, Performance API, workers, IndexedDB, WebGPU capability checks, and local CSV export, they form a compact surface for reproducing, explaining, and comparing runtime quality.

制作に使えそうな技術メモ

Production note

動画 API の timestamp は単調増加に保ち、Task が single-flight なら呼び出し中は newest-wins の pending slot を一つにします。実測値には移動平均と hysteresis を入れ、70/125/220ms のようなしきい値をまたいで品質が点滅しないようにします。計測イベントは入力内容と分離し、同意、保持期間、送信先を UI で説明します。

Keep video API timestamps monotonic. When a Task is single-flight, keep one newest-wins pending slot while a call runs. Add moving averages and hysteresis to measurements so quality does not flicker across thresholds such as 70/125/220 ms. Separate metric events from input content and explain consent, retention, and destination in UI.
