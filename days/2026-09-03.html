今日の重要トピック

  1. Image Embedder は画像を数値表現に変換し、2つの画像の similarity 比較などに使う Web ML の土台になる。

    Image Embedder turns image data into numeric representations and is a useful Web ML foundation for comparing two images by similarity.

  2. JavaScript API reference では `ImageEmbedder.cosineSimilarity()` が用意され、埋め込み同士の比較を Task 側の型に沿って実装できる。

    The JavaScript API reference provides `ImageEmbedder.cosineSimilarity()`, so embedding comparison can stay aligned with Task result types.

  3. Web guide は `embed()` / `embedForVideo()` が同期実行で UI thread を塞ぎ得ると明記しており、動画や連続比較では Worker 化が重要になる。

    The Web guide states that `embed()` / `embedForVideo()` run synchronously and can block the UI thread, making workers important for video or repeated comparisons.

  4. 公式 mediapipe-samples-web の Image Embedder は MobileNet V3 Small を既定モデルにし、画像を `ImageBitmap` にして Worker へ送る構成になっている。

    The official mediapipe-samples-web Image Embedder uses MobileNet V3 Small by default and sends images as `ImageBitmap` objects to a worker.

    An npm check on 2026-09-03 JST showed `@mediapipe/tasks-vision` at 1.0.1 and `@mediapipe/tasks-genai` at 0.10.29.

注目事例と何が面白いか

Notable example and why it matters

今日の注目は Image Embedder です。Image Segmenter や Detector のように目で結果を確認しやすい Task と違い、Image Embedder は画像をベクトルに変換してから similarity を読むため、UI 側で「近い」「確認が必要」「別物」をどう扱うかが体験を決めます。公式サンプルが worker に画像を渡して比較している点も、単発デモではなく継続比較の設計として面白いところです。

Today's notable task is Image Embedder. Unlike Segmenter or Detector outputs, embeddings are not directly visual; the app has to turn vector similarity into product decisions such as close, needs review, or different. The official sample's worker-based image comparison is also interesting because it points toward repeated comparison rather than a one-off demo.

表現・インタラクションのアイデア

Expression and interaction idea

本命サンプル `Image Embedder Similarity Scout` は、2枚の合成画像を描き、明るさ・色・輪郭から16次元の疑似埋め込みを作って cosine similarity を表示します。これは本物の `ImageEmbedder.embed()` を入れる前に、スコア表示、差分バー、判定文、API preflight を確認するための足場です。派生の `Similarity Threshold Router` は、同じ発展案のうちスコアを実アプリの分岐へ変換する部分だけを切り出し、auto match / human review / new cluster の境界を触れるようにしました。

The main sample, `Image Embedder Similarity Scout`, draws two synthetic images, creates a 16-dimensional pseudo embedding from brightness, color, and edge features, and displays cosine similarity. It is a scaffold for checking score display, delta bars, verdict copy, and API preflight before wiring in real `ImageEmbedder.embed()`. The derivative `Similarity Threshold Router` isolates one next-step idea: converting similarity scores into app behavior across auto match, human review, and new cluster routes.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

蓄積できるデータは、画像ペア、疑似特徴ベクトル、cosine similarity、上位候補との差分、判定ルート、しきい値、API preflight 結果、ユーザーが調整した variation / color drift / noise です。これを実 Image Embedder、Image Classifier のラベル、Object Detector の bbox、Image Segmenter の mask、localStorage の履歴、IndexedDB の小型ギャラリー、Web Worker の latency 計測と組み合わせると、手元画像の重複検出、似た構図検索、候補レビューUI、セグメント済み領域だけの類似検索に発展できます。

The samples can accumulate image pairs, pseudo feature vectors, cosine similarity, top-candidate margin, route decisions, thresholds, API preflight results, and user-tuned variation / color drift / noise values. Combined with real Image Embedder outputs, Image Classifier labels, Object Detector boxes, Image Segmenter masks, localStorage history, an IndexedDB mini gallery, and Web Worker latency metrics, they can grow into duplicate detection, composition search, candidate review UI, and mask-scoped similarity search.

制作に使えそうな技術メモ

Production note

静的HTMLでは `@mediapipe/tasks-vision@1.0.1/+esm` を dynamic import する preflight だけを置き、実推論なしでも動く疑似特徴量で UI を先に固めました。本番に進める場合は `FilesetResolver.forVisionTasks()` と MobileNet V3 Small の model URL を Worker 内で初期化し、`createImageBitmap()` で受け取った画像に `embed()` を実行し、`ImageEmbedder.cosineSimilarity()` で比較します。`embedForVideo()` を使う連続処理では、同期推論が UI thread を塞がないよう Worker とフレーム間引きを前提にします。

The static HTML only uses a dynamic import preflight for `@mediapipe/tasks-vision@1.0.1/+esm`; the UI is designed with pseudo features so it works without live inference. For production, initialize `FilesetResolver.forVisionTasks()` and the MobileNet V3 Small model URL inside a worker, run `embed()` on `createImageBitmap()` inputs, and compare with `ImageEmbedder.cosineSimilarity()`. For repeated `embedForVideo()` processing, assume workers and frame skipping so synchronous inference does not block the UI thread.

If you try one thing

Then raise `Variation` and `Color drift` to see how far the score drops. `Nudge B` tests how a small visible change affects similarity. In the derivative sample, move the `Match` and `Review` thresholds to see how the same top score can trigger different product routes.
