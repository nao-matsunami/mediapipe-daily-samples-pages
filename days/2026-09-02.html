今日の重要トピック

  1. Image Segmenter の Web 実装では category mask と confidence masks を使い分けるため、表示品質だけでなくマスク寿命と解放境界を UI 側で意識する必要がある。

    Image Segmenter web apps need to choose between category masks and confidence masks, so UI code should care about mask lifetime and release boundaries, not only visual quality.

  2. 公式 mediapipe-samples-web の Image Segmenter worker は OffscreenCanvas / WebGL で mask bitmap を作り、postMessage transfer 後に result mask を close する構成になっている。

    The official mediapipe-samples-web Image Segmenter worker renders mask bitmaps with OffscreenCanvas/WebGL, transfers the bitmap through postMessage, and closes result masks.

  3. DrawingUtils の confidence mask 描画は default / overlay texture のブレンドとして扱えるため、しきい値や alpha curve を別UIで調整してから本体へ入れると試行錯誤しやすい。

    DrawingUtils treats confidence-mask display as a blend between default and overlay textures, making threshold and alpha-curve tuning useful before wiring the behavior into the main app.

  4. Face Landmarker Web guide と同様に、Web Tasks の同期推論は UI thread を塞ぎ得るため、動画セグメンテーションでは Worker、フレーム間引き、描画予算の見える化が重要になる。

    As with the Face Landmarker Web guide, Web Tasks synchronous inference can block the UI thread, so video segmentation benefits from workers, frame skipping, and visible paint budgets.

  5. npm 確認では 2026-09-02 JST 時点で `@mediapipe/tasks-vision` は 1.0.1、`@mediapipe/tasks-genai` は 0.10.29 だった。

    An npm check on 2026-09-02 JST showed `@mediapipe/tasks-vision` at 1.0.1 and `@mediapipe/tasks-genai` at 0.10.29.

注目事例と何が面白いか

Notable example and why it matters

今日の注目は、公式の Image Segmenter サンプルが単にマスクを表示するだけでなく、Worker 内で OffscreenCanvas / WebGL を使って描画用 bitmap を作り、転送後に result mask を close している点です。セグメンテーションは見た目の派手さに目が行きがちですが、動画で毎フレーム mask を生成する場合、close忘れや保持しすぎは UI の重さとして現れます。

Today's notable point is that the official Image Segmenter sample does more than display a mask: its worker uses OffscreenCanvas/WebGL to produce a drawable bitmap and closes result masks after transfer. Segmentation demos often focus on the visual result, but in per-frame video pipelines, forgotten closes or excessive retention show up as UI cost.

表現・インタラクションのアイデア

Expression and interaction idea

本命サンプル `Image Segmenter Mask Lifecycle Sentinel` は、category mask と confidence mask の疑似フレームを作り、`close after draw` と `retain for inspection` を切り替えながら、保持マスク数、推定バイト数、描画コスト、フレーム予算を表示します。派生の `Confidence Mask Alpha Curve Lab` は、発展案のうち confidence 値を半透明UIへ変換する部分だけを切り出し、threshold、gamma、edge boost を触って境界の出方を調整できます。

The main sample, `Image Segmenter Mask Lifecycle Sentinel`, generates synthetic category and confidence mask frames and lets you switch between `close after draw` and `retain for inspection` while watching retained mask count, estimated bytes, paint cost, and frame budget. The derivative `Confidence Mask Alpha Curve Lab` isolates one next-step idea: turning confidence values into a translucent UI overlay with threshold, gamma, and edge-boost controls.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

蓄積できるデータは、mask type、mask size、frame cost、budget ratio、retained mask count、estimated bytes、close/retain event、alpha threshold、gamma、edge pixel count、active area ratio です。これを Image Segmenter の実 confidence masks、Object Detector の bounding box、Hand Landmarker の pointer、Canvas captureStream、WebCodecs、Worker postMessage latency、localStorage の session replay と組み合わせると、背景ぼかし、身体領域だけの編集、手元だけのマスク修正、セグメント品質の A/B 比較に発展できます。

The samples can accumulate mask type, mask size, frame cost, budget ratio, retained mask count, estimated bytes, close/retain events, alpha threshold, gamma, edge pixel count, and active-area ratio. Combined with real Image Segmenter confidence masks, Object Detector boxes, Hand Landmarker pointers, Canvas captureStream, WebCodecs, worker postMessage latency, and localStorage session replay, they can support background blur, body-only editing, hand-guided mask repair, and segmentation quality A/B tests.

制作に使えそうな技術メモ

Production note

静的HTMLでは実モデル推論に依存しすぎず、まず synthetic mask を `Uint8Array` / `Float32Array` として生成し、描画後に `close()` 相当の解放境界を明示しました。API preflight では `@mediapipe/tasks-vision@1.0.1/+esm` と同じ version の wasm path を読み、CDN/WASM 到達性だけ確認できます。本番では `ImageSegmenter.createFromOptions()` を Worker に置き、mask を描画用 bitmap に変換してから元 mask を close する流れにします。

The static HTML avoids depending on live model inference first: it generates synthetic masks as `Uint8Array` / `Float32Array` and makes the release boundary explicit with a `close()`-like method after drawing. The API preflight imports `@mediapipe/tasks-vision@1.0.1/+esm` and a same-version wasm path to confirm CDN/WASM availability. In production, `ImageSegmenter.createFromOptions()` should live in a worker, convert masks into drawable bitmaps, and close the original masks.

試すならこれ

If you try one thing

`Image Segmenter Mask Lifecycle Sentinel` を開き、`Start loop` を押してから mode を `retain for inspection` に変えます。保持マスク数と推定バイト数が増え、budget meter も赤寄りになります。次に `Flush retained masks` で戻し、`close after draw` のまま mask size と paint cost を上げると、解放していても描画処理自体がフレーム予算を食うことがわかります。派生では threshold と gamma を上げ、境界のにじみを抑えられるかを見ます。

Open `Image Segmenter Mask Lifecycle Sentinel`, start the loop, and switch mode to `retain for inspection`. The retained mask count and estimated bytes grow, and the budget meter moves toward hot. Then flush retained masks and, while staying in `close after draw`, raise mask size and paint cost to see that drawing itself can exceed the frame budget even when masks are released. In the derivative sample, raise threshold and gamma to reduce boundary bleed.
