Notable example and why it matters

The v1.1.0 Web Tasks update explicitly covers not only UniversalEmbedder / SemanticRetriever additions but prevention of overlapping WASM embedding calls and stats logging. It shows that Web ML quality can fail through asynchronous completion order, display correctness, and consent handling—not just model accuracy.

表現・インタラクションのアイデア

Expression and interaction idea

本命の `Web Embedding Run Fence Console` は、入力 burst と simulated latency を変え、generation fence + latest queue と naive concurrent calls を比較します。派生の `Tasks Stats Consent Budget Meter` は、同意、保持期間、セッション予算を変えると各 metric が send / hold / stop にどう移るかを触れます。

The main console varies input bursts and simulated latency to compare a generation fence + latest queue with naive concurrent calls. The derivative meter shows how consent, retention, and session budget move each metric among send / hold / stop.

Useful data includes generation, queue depth, start/end time, stale-discard count, maximum inflight, inference latency, delegate fallback, cache hits, consent state, retention policy, and event budget. 制作に使えそうな技術メモ

Production note

UI state に request generation を持ち、開始時の generation と完了時の generation が異なる結果は描画しない設計が基本です。Task API が single-flight 前提なら queue は newest-wins か明示的な backpressure にし、計測は入力内容と切り離して、送るイベント名・保持・同意の状態を設定画面で説明できるようにします。

Keep a request generation in UI state and do not render a result when the generation at completion differs from the one at start. If a Task API is single-flight, use newest-wins queuing or explicit backpressure. Separate metrics from input content and explain event names, retention, and consent in settings.

今日のミニ試作候補

Today's mini prototype candidate

採用した本命は `Web Embedding Run Fence Console` です。実際に動く部分は、入力 burst を実行し、policy に応じて synthetic embedding job を accepted / stale に振り分け、最大 inflight と log を更新するところです。次に足すなら実 UniversalEmbedder、Worker abort、warm-up、IndexedDB cache を接続します。派生は `Tasks Stats Consent Budget Meter` で、同意・保持期間・budget によって simulated task metric を send / hold / stop に振り分けます。次に足すなら consent record と端末内 audit export を足します。

The selected main prototype is `Web Embedding Run Fence Console`. Its working behavior runs input bursts, routes synthetic embedding jobs to accepted / stale according to policy, and updates maximum inflight and the log. Next connect UniversalEmbedder, worker abort, warm-up, and IndexedDB cache. The derivative is `Tasks Stats Consent Budget Meter`, routing simulated task metrics to send / hold / stop by consent, retention, and budget. Next add a consent record and local audit export.
