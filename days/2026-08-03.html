今日の重要トピック

  1. Interactive Image Segmenter は画像上の 1 点を手がかりに、その点を含む対象物と背景を分ける MediaPipe Tasks の Vision タスク。

    Interactive Image Segmenter is a MediaPipe Tasks vision task that separates an object from the background using a point in the image as a hint.

  2. Web 実装では `@mediapipe/tasks-vision`、`FilesetResolver.forVisionTasks()`、`InteractiveSegmenter.createFromOptions()`、MagicTouch モデルを組み合わせる。

    The web implementation combines `@mediapipe/tasks-vision`, `FilesetResolver.forVisionTasks()`, `InteractiveSegmenter.createFromOptions()`, and the MagicTouch model.

  3. 出力は `CATEGORY_MASK` または `CONFIDENCE_MASK` を選べ、今日の試作では uint8 の category mask を半透明オーバーレイにした。

    The output can be `CATEGORY_MASK` or `CONFIDENCE_MASK`; today's prototype renders the uint8 category mask as a translucent overlay.

  4. 公式 Web ガイドは `segment()` / `segmentForVideo()` が同期実行で UI スレッドをブロックし得る点を明示しており、動画化するなら Worker 分離が次の論点。

    The official web guide notes that `segment()` and `segmentForVideo()` run synchronously and can block the UI thread, making Worker isolation the next concern for video.

  5. モデルや CDN が使えない環境でも UI と観察軸を確認できるよう、クリック点ベースの radial fallback mask を入れた。

    A point-based radial fallback mask keeps the UI and observation flow usable when the model or CDN is unavailable.

注目事例と何が面白いか

Notable example and why it matters

今日の注目は MediaPipe Interactive Image Segmenter です。通常の Image Segmenter がモデル側のカテゴリや人物領域を一括で返すのに対し、Interactive Segmenter はユーザーが指定した点を ROI として使い、その点に対応する対象物だけを切り出します。写真編集、注釈付け、教材、EC の商品切り抜きなど、ユーザーの意図を 1 点で渡せるところが面白いです。

Today's focus is MediaPipe Interactive Image Segmenter. Unlike a regular Image Segmenter that returns model-defined categories or person regions, Interactive Segmenter uses a user-selected point as an ROI and cuts out the object associated with that point. That makes it interesting for photo editing, annotation, learning tools, and product cutouts where intent can be expressed with one click.

表現・インタラクションのアイデア

Expression and interaction idea

自作サンプルでは、合成された卓上オブジェクトを最初から表示し、クリックした点を黄色のクロスヘアで残しつつ、対象マスクを緑の半透明オーバーレイで重ねます。アップロードした静止画やカメラのフリーズフレームにも同じ操作を使えるので、クリック位置とマスクの関係を短い実験として見られます。

The original sample starts with a synthetic tabletop image, keeps the clicked point as a yellow crosshair, and overlays the target mask in translucent green. The same interaction works for uploaded stills and frozen camera frames, making the relationship between click position and mask output easy to inspect.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

このサンプルで蓄積できるクリック座標、推論時間、マスク面積、入力種別、しきい値、オーバーレイ設定は、選択操作の品質ログとして使えます。Image Segmenter と組み合わせて人物マスクとの差分を見たり、Object Detector の bounding box 内でクリック候補を提示したり、WebGL でマスク境界にエフェクトをかけたりできます。LLM に画像編集指示を作らせる場合も、クリック点とマスクを編集対象の構造化入力にできます。

The sample can accumulate click coordinates, inference time, mask coverage, input type, threshold, and overlay settings as quality logs for selection interactions. It can be combined with Image Segmenter to compare against person masks, with Object Detector to suggest click candidates inside boxes, or with WebGL to apply effects on mask boundaries. When pairing with an LLM for image-edit instructions, the click point and mask become structured edit targets.

制作に使えそうな技術メモ

Production note

Web 版は `FilesetResolver.forVisionTasks()` で WASM を解決し、`InteractiveSegmenter.createFromOptions()` に MagicTouch の `modelAssetPath` と `outputCategoryMask: true` を渡します。クリック座標は表示矩形から 0-1 に正規化して `{ keypoint: { x, y } }` として `segment()` へ渡しました。category mask は `DrawingUtils.drawCategoryMask()` で別 Canvas に描き、coverage を alpha 値から数えています。

The web version resolves the Wasm files with `FilesetResolver.forVisionTasks()` and passes the MagicTouch `modelAssetPath` plus `outputCategoryMask: true` to `InteractiveSegmenter.createFromOptions()`. Click coordinates are normalized to 0-1 from the display rectangle and passed to `segment()` as `{ keypoint: { x, y } }`. The category mask is drawn to another Canvas with `DrawingUtils.drawCategoryMask()`, and coverage is counted from alpha values.
