注目事例と何が面白いか

Notable example and why it matters

v1.1.0 の JavaScript 更新は、Web Tasks に landmark ごとの presence score を出し、UniversalEmbedder / SemanticRetriever の Web API を広げました。これは「何を認識したか」だけでなく「どれくらい確からしいか」「候補をどんな幅で見せるか」を UI が扱えるということです。小さな数値を表示するだけで終えず、見た目と選択へ翻訳する余地があります。

The v1.1.0 JavaScript updates expose per-landmark presence and broaden Web APIs for UniversalEmbedder and SemanticRetriever. UI can now handle not just what was recognized, but how trustworthy it is and how broadly candidates should be shown. There is room to translate small values into appearance and selection rather than merely display them.

表現・インタラクションのアイデア

Expression and interaction idea

本命 `Presence-Weighted Landmark Brush` はキャンバスをドラッグして疑似 landmark を作り、presence threshold、smoothing、不確かさを動かします。明るさ・太さ・線の切断が即座に変わります。派生 `Retrieval Diversity Dial` は、関連度が似た候補群から、diversity dial に応じて異なる cluster を選ぶ実演です。どちらも結果をブラックボックスのまま表示しないための UI 実験です。

The main `Presence-Weighted Landmark Brush` creates synthetic landmarks by dragging and changes threshold, smoothing, and uncertainty; brightness, width, and breaks update immediately. The derivative `Retrieval Diversity Dial` selects different clusters from similarly relevant candidates as its dial changes. Both are UI experiments for avoiding black-box result display.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

残すと価値があるのは landmark の x/y/z、presence、visibility、timestamp、平滑化前後の座標、retrieval の score、embedding の距離、cluster、ユーザーが採用・除外した候補です。Hand / Pose / Face Landmarker、UniversalEmbedder、SemanticRetriever、Pointer Events、Web Audio、IndexedDB、端末内 JSON export と組み合わせれば、ジェスチャー線の練習器や、検索の意図を学習しない個人用探索面へ発展します。

Useful records include landmark x/y/z, presence, visibility, timestamps, coordinates before/after smoothing, retrieval scores, embedding distance, cluster, and accepted/rejected candidates. Combined with Hand/Pose/Face Landmarker, UniversalEmbedder, SemanticRetriever, Pointer Events, Web Audio, IndexedDB, and local JSON export, they can grow into a gesture-line practice tool or a private exploratory surface.

制作に使えそうな技術メモ

Production note

presence と visibility は同じ意味として混ぜず、Task が返す値の定義を記録して UI の閾値を端末・モデルごとに調整します。平滑化は low presence 時に強くしすぎると古い形を残すため、timestamp と速度も併用します。retrieval では score の正規化、同一 cluster の重複、候補選択の説明を分け、検索語や embedding を外部送信する場合は同意と保存期間を明確にします。

Do not conflate presence and visibility: record definitions returned by the Task and tune UI thresholds per device and model. Excess smoothing at low presence can preserve stale shapes, so combine timestamps and speed. For retrieval, separate score normalization, same-cluster duplication, and selection explanation; make consent and retention clear if queries or embeddings leave the device.

If you try one thing

本命で不確かさを 0.6 以上にし、threshold を 0.45 前後で上下させると、同じ軌跡でも線がどこで切れるかが見えます。派生は多様性を 0 から 0.8 へ動かし、関連度の小さな損失で cluster 数が増える様子を確認してください。

In the main sample, raise uncertainty above 0.6 and vary threshold around 0.45 to see where the same path breaks. In the derivative, move diversity from 0 to 0.8 and observe clusters increase with a small relevance trade-off.
