注目事例と何が面白いか

Notable example and why it matters

今日の注目は Text Embedder を「文章をベクトルにする task」だけでなく、2文比較、重複検出、検索 cache、プロンプト候補の近さ判定として扱うことです。公式 API は `embed(text)` が同期的に結果を待つこと、`TextEmbedder.cosineSimilarity()` が embedding 同士の比較 utility として用意されていることを示しており、UI では worker、cache、threshold、quantized embedding の誤差吸収が設計ポイントになります。

Today's notable angle is treating Text Embedder not only as a task that turns text into vectors, but also as a building block for pair comparison, duplicate detection, search caches, and prompt candidate routing. The official API shows that `embed(text)` waits synchronously and that `TextEmbedder.cosineSimilarity()` is provided for comparing embeddings, making workers, caches, thresholds, and quantized-embedding tolerance the important UI design points.

表現・インタラクションのアイデア

Expression and interaction idea

本命サンプル `Text Embedder Pair Similarity Console` は、2つの文章を編集し、synthetic embedding の差分、cosine similarity、量子化、同期 cost、accept / review route を可視化します。派生の `Semantic Cache Route Lab` は、問い合わせ stream が過去 embedding cache に近いかを見て、reuse、re-embed、human review を切り替えます。文章 UI では分類ラベルよりも「この入力は既存結果を使い回してよいか」を見せる方が実運用に近いです。

The main sample, `Text Embedder Pair Similarity Console`, lets you edit two texts and visualize synthetic embedding deltas, cosine similarity, quantization, synchronous cost, and accept / review routing. The derivative, `Semantic Cache Route Lab`, watches whether a query stream is close to previous embedding-cache entries and switches between reuse, re-embed, and human review. For text UI, showing whether an input can safely reuse an existing result is often closer to production needs than showing a simple label.

Possibilities unlocked by sample data and combinations

蓄積できるデータは、入力文、token frequency、embedding vector、float / quantized mode、cosine similarity、threshold decision、sync cost、cache age、TTL decay、reuse count、review count、re-embed count です。Text Embedder、Language Detector、Text Classifier、Image Embedder、AudioEmbedder、IndexedDB、Web Worker、LiteRT-LM / on-device LLM と組み合わせると、ローカル検索、重複問い合わせ抑制、類似メモ推薦、画像・音・文章の cross-modal event log、プライバシー重視のプロンプト cache に発展できます。

The samples can collect input text, token frequency, embedding vectors, float / quantized mode, cosine similarity, threshold decisions, sync cost, cache age, TTL decay, reuse counts, review counts, and re-embed counts. Combined with Text Embedder, Language Detector, Text Classifier, Image Embedder, AudioEmbedder, IndexedDB, Web Workers, and LiteRT-LM / on-device LLMs, this can grow into local search, duplicate-query suppression, similar-note recommendations, cross-modal event logs for image / audio / text, and privacy-oriented prompt caches.

制作に使えそうな技術メモ

Production note

実装時は `FilesetResolver.forTextTasks()`、`TextEmbedder.createFromModelPath()`、`TextEmbedder.createFromOptions()`、`TextEmbedder.embed(text)`、`TextEmbedder.cosineSimilarity()`、`Embedding.floatEmbedding`、`Embedding.quantizedEmbedding` を分けて計測します。文章が短い場合は similarity が揺れやすいため、しきい値は task ごとに UI で調整できるようにし、同期 embed は worker に逃がして main thread の入力遅延を避けます。cache は semantic score だけでなく age と provenance を表示すると安全です。

For implementation, measure `FilesetResolver.forTextTasks()`, `TextEmbedder.createFromModelPath()`, `TextEmbedder.createFromOptions()`, `TextEmbedder.embed(text)`, `TextEmbedder.cosineSimilarity()`, `Embedding.floatEmbedding`, and `Embedding.quantizedEmbedding` separately. Short text can produce unstable similarity, so thresholds should be adjustable per task, and synchronous embedding should move to a worker to avoid main-thread input delay. For caches, expose age and provenance as well as semantic score.
