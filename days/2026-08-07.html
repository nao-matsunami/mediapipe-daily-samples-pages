    `classify(audioData, sampleRate)` is a synchronous API that accepts a `Float32Array` and sample rate, so Worker execution matters for continuous microphone classification.

    The Audio Classifier overview lists score threshold, top-k, allowlist / denylist, and locale labels, all of which map directly to public UI controls.

注目事例と何が面白いか

Notable example and why it matters

今日の注目は、Audio Classifier を「結果ラベルを見るだけのデモ」ではなく、音声入力そのものの形を理解する UI として扱うことです。公式ガイドでは `Float32Array` の raw audio と sample rate を `classify()` に渡す流れが示され、overview では score threshold や top-k がタスク機能として整理されています。今日のサンプルは、speech pulse、music tone、noise bed を混ぜて 1.6 秒の音を作り、波形、ゼロ交差率、スペクトル重心、イベント score を同時に見られるようにしました。

Today's notable angle is treating Audio Classifier not as a label-only demo, but as a UI for understanding the shape of the audio input itself. The official guide shows raw `Float32Array` audio and sample rate flowing into `classify()`, while the overview organizes score threshold and top-k as task features. Today's sample mixes speech pulse, music tone, and noise bed into a 1.6 second clip, then displays waveform, zero-crossing rate, spectral centroid, and event scores together.

表現・インタラクションのアイデア

Expression and interaction idea

サンプルは Synthesize、Play、Load MediaPipe、Mic 1.6s の入口を持ちます。スライダーで声っぽい周期、音楽的な和音、ノイズを混ぜ、threshold を動かすと top events の残り方が変わります。MediaPipe をロードできる環境では YamNet のカテゴリを表示し、失敗しても同じ音声バッファを使う簡易ヒューリスティックが動くため、公開アーカイブとしては常に操作できます。

The sample exposes Synthesize, Play, Load MediaPipe, and Mic 1.6s controls. Sliders mix speech-like pulses, tonal chords, and noise, while the threshold changes which top events survive. When MediaPipe loads, it displays YamNet categories; when it fails, a heuristic over the same audio buffer keeps the public archive interactive.

サンプルデータの可能性と組み合わせ

Possibilities unlocked by sample data and combinations

蓄積できるデータは raw audio、RMS、ゼロ交差率、スペクトル重心、threshold、イベント score、マイク権限の成否です。Gesture Recognizer や Hand Landmarker と組み合わせれば、手の動きで音を作り、その音を Audio Classifier で読むフィードバック楽器になります。Pose Landmarker と合わせると運動中の音イベント、Face Landmarker と合わせると発話や笑いの反応可視化、WebRTC と合わせると遠隔セッションの軽量な音イベントログに発展できます。

The accumulated data includes raw audio, RMS, zero-crossing rate, spectral centroid, threshold, event scores, and microphone permission results. Combined with Gesture Recognizer or Hand Landmarker, hand motion can generate sound that Audio Classifier reads back as a feedback instrument. With Pose Landmarker it can log exercise sound events, with Face Landmarker it can visualize speech or laughter reactions, and with WebRTC it can become a lightweight remote-session audio-event log.

制作に使えそうな技術メモ

Production note

実装では Web Audio の `AudioContext` で 16 kHz / 1.6 秒の mono buffer を作り、`Float32Array` として扱います。MediaPipe 側は `@mediapipe/tasks-audio@0.10.22` を CDN import し、`FilesetResolver.forAudioTasks()` で WASM を解決してから `AudioClassifier.createFromOptions()` に YamNet の modelAssetPath を渡します。公式 API の `classify(audioData, sampleRate)` は同期実行なので、長時間のマイクストリームでは `ScriptProcessor` 風の実装をそのまま本番にせず、Worker / AudioWorklet へ逃がす設計が必要です。

The implementation creates a 16 kHz / 1.6 second mono buffer with Web Audio and treats it as a `Float32Array`. On the MediaPipe side, it imports `@mediapipe/tasks-audio@0.10.22`, resolves WASM through `FilesetResolver.forAudioTasks()`, and passes YamNet's model asset path to `AudioClassifier.createFromOptions()`. Because the official `classify(audioData, sampleRate)` API runs synchronously, long microphone streams should move away from a simple main-thread processor toward Worker / AudioWorklet execution.

試すならこれ

If you try one thing

まず Synthesize のまま Speech pulse、Music tone、Noise bed を動かし、波形と top events がどう変わるか見ます。次に Score threshold を上げ下げして、同じ音でも公開 UI で残るイベントが変わることを確認します。最後に Load MediaPipe を押し、CDN と YamNet が読み込める環境なら MediaPipe の実カテゴリ、失敗する環境なら fallback のイベント score を比較します。

First keep Synthesize active and move Speech pulse, Music tone, and Noise bed to see how waveform and top events change. Then move Score threshold to confirm that the same sound produces different visible events. Finally press Load MediaPipe: if CDN and YamNet load, compare real MediaPipe categories; if not, compare the fallback event scores.

俯瞰メモ

Bird's-eye memo

これまでの Vision 中心サンプルに Audio が加わり、手、画像マスク、クリック分割、物体、姿勢、顔、音という入力モダリティが広がりました。MediaPipe Tasks の日次アーカイブでは、モデルが重くても synthetic fallback を用意すると、公式デモ一覧ではなく自作サンプルとして毎日触れる状態を保てます。Audio は UI thread blocking、マイク権限、sample rate、音声長という Vision とは別の実装リスクを可視化しやすい題材です。

Audio now joins the Vision-heavy archive, widening the input modalities from hands, image masks, click segmentation, objects, pose, and face to sound. In a daily MediaPipe Tasks archive, synthetic fallbacks keep each original sample touchable even when models are heavy. Audio is useful because it exposes implementation risks that differ from Vision: UI-thread blocking, microphone permission, sample rate, and clip length.
